# App 097 · 智能家居中控设计

## 产品定位

HABITAT/97 是一个面向普通家庭的浏览器端住宅数字孪生中控。页面的单一任务是让用户在一个屏幕内看懂“家现在怎么样”，并能完成设备控制、场景切换和自动化管理。它不连接真实硬件，不伪装成云端服务；全部状态保存在当前浏览器，可直接部署到 GitHub Pages 并离线演示核心流程。

成功标准：用户能在 30 秒内完成四件事——切换回家/离家/观影/睡眠场景；在户型图上选择房间；调节灯光、空调、窗帘等设备；确认总功率、活跃设备和最近动作同步变化。刷新页面后，设备与规则状态应保留。

## 方案比较

1. **推荐：单页住宅数字孪生。** 户型图承担导航与实时状态表达，右侧设备抽屉负责精细控制。信息关系清晰，最能体现“中控”，静态部署也足够完整。
2. **设备卡片后台。** 实现成本较低，但更像通用管理面板，房间、设备和场景之间的空间关系不直观。
3. **手机遥控器。** 适合单设备操作，但无法同时呈现整屋能耗、自动化与跨房间联动。

因此采用方案 1，并用纯 HTML、CSS、JavaScript 保持零依赖和可审计性。

## 信息架构与数据流

页面分为顶部家庭状态栏、左侧场景与自动化轨道、中部交互户型、右侧设备与能耗控制台。户型内每个房间显示温度、活跃设备数与代表性状态；选择房间后，右侧只展示该房间设备。场景按钮通过纯函数一次性更新多个设备，设备单控再通过同一状态入口更新。所有变化都会重新计算瞬时功率、活跃数和舒适度，并写入最近动作记录与 `localStorage`。

```text
┌ 家庭状态 / 天气 / 当前模式 ─────────────────────────────┐
│ 场景轨道      │ 可交互住宅剖面             │ 实时控制台 │
│ 回家  离家    │ 客厅 ─ 厨房 ─ 阳台          │ 房间设备   │
│ 观影  睡眠    │ 卧室 ─ 书房 ─ 玄关          │ 功率曲线   │
│ 自动化规则    │ 房间状态与能量流            │ 最近动作   │
└───────────────┴────────────────────────────┴────────────┘
```

异常处理以本地可恢复为原则：损坏的缓存会回退到默认状态；未知设备或场景不会改变状态；存储不可用时仍可在当前会话操作，并用轻提示说明。重置操作需要二次确认。

## 视觉系统

视觉来自建筑师的采光平面图，而不是常见深色霓虹后台。背景使用 **Chalk `#EEF1EC`**，主要文字 **Graphite `#17231F`**，交互主色 **Circuit `#2459D3`**，供暖/告警 **Terracotta `#E96445`**，太阳能 **Sun `#F2C14E`**，舒适状态 **Leaf `#3C9D76`**。标题使用窄体系统字族 `Arial Narrow`，正文使用 `Microsoft YaHei UI` / `PingFang SC`，数据使用 `SFMono-Regular` / `Consolas`。

标志性元素是一张“会呼吸的户型图”：房间不是装饰卡片，而是设备状态的空间索引；场景切换时，一条电力轨迹依次点亮受影响房间。其余界面保持纸面化、低圆角、细描边，避免装饰噪音。桌面采用三栏，移动端改为场景横滑、户型在上、设备在下；键盘焦点清晰，并尊重 `prefers-reduced-motion`。

## 功能边界与验证

首版包含 6 个房间、10 个模拟设备、4 个场景、3 条可开关自动化、实时能耗估算、7 日用电趋势、动作日志、本地持久化和恢复默认。它不包含账号、远程推送、真实设备配网、厂商 API 或真实电费结算。

核心状态函数通过 Node 内置测试覆盖：默认状态隔离、设备更新边界、场景联动、能耗计算、自动化触发、序列化恢复。浏览器冒烟测试覆盖场景切换、房间筛选、设备单控、刷新持久化、重置、桌面与移动布局，以及控制台错误。根追踪器另外验证 97 号名称、说明、部署链接和官方完成状态。
