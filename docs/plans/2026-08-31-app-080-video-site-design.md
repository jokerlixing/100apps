# App #080 视频网站 Demo 设计

## 产品定位

`CHANNEL/80 · 放映局` 面向想在一个短暂休息时段里看完一部短片的人。页面只做一件事：让观众从三部公开短片或自己的本地视频中选片，在一个不离开播放器的界面里观看、发定时弹幕并继续下一部。它是可直接部署到 GitHub Pages 的静态作品集 Demo，不做账号、上传服务器、版权分发、推荐算法或付费功能。

## 方案比较与选择

1. 只使用远程公开视频：打开即播，但视频源失效时无法验收。
2. 只使用本地文件：隐私与可靠性最好，但首屏没有可演示内容。
3. 远程片单 + 本地临时导入：兼顾开箱体验、GitHub Pages 部署与离线自检。

采用方案 3。内置片单引用 W3C、MDN 的公开示例视频，不把大体积媒体提交到仓库；用户可选择本机 `video/*` 文件，文件只通过对象 URL 在当前标签页播放，刷新即消失。

## 视觉方向

- **主题**：旧式社区放映室的节目单与现代网页播放器结合。
- **色板**：放映厅墨蓝 `#101727`、幕布蓝 `#18233A`、票根米白 `#F2E7D2`、镜头琥珀 `#E9A45B`、提示天蓝 `#8EC7D3`、警示珊瑚 `#D96C6C`。
- **字体**：标题用窄体 `Bahnschrift SemiCondensed / Arial Narrow`，正文用 `Microsoft YaHei / system-ui`，时间与编号用 `Cascadia Mono / Consolas`。
- **布局**：桌面端为 8:4 的主播放器与节目单；手机端变为单列，弹幕输入保持在播放器之后。
- **标志性元素**：播放器左侧的“放映信号轨”，随播放进度点亮刻度，并标出当前弹幕密度；它编码真实播放状态，而非装饰。

```text
┌─ 信号轨 ────────────────────────────────┬─ 今晚节目单 ─┐
│  ● 00:38  ┌──────────────────────────┐ │  01 短片     │
│  ○ 01:14  │       视频 + 弹幕层       │ │  02 短片     │
│  ○ 02:03  └──────────────────────────┘ │  03 短片     │
│             弹幕输入 / 颜色 / 发送      │  本地选片     │
└────────────────────────────────────────┴──────────────┘
```

深色影院不是使用单一荧光色的通用模板：米白节目票、琥珀投影状态和天蓝交互反馈共同建立放映室语义；动画只用于弹幕横穿与信号轨进度，其他区域保持克制。

## 交互与数据流

片单数据写在客户端。切片时保存上一部进度并载入该片最后进度；播放结束按“自动连播”设置进入下一部。弹幕提交时记录 `videoId + currentTime + text + color`，清洗控制字符并限制 60 字；播放过程中只把当前时间窗口内尚未渲染的弹幕分配到六条轨道。弹幕、进度、音量、倍速和连播偏好保存在 `localStorage`，本地视频的二进制与对象 URL 不持久化。

远程视频加载失败时，页面显示明确错误并引导用户换片或选择本地文件。存储损坏时回退到默认设置；所有用户文本只通过 `textContent` 渲染。键盘可操作播放、静音、弹幕开关和片单；焦点可见，窄屏可用，并尊重 `prefers-reduced-motion`。

## 验收范围

- 三部内置短片可切换，本地视频可临时加入并播放。
- 播放、暂停、拖动、音量、静音、倍速、全屏和自动连播可用。
- 弹幕按视频和时间持久化，可发送、显示/隐藏和清空当前视频弹幕。
- 刷新后恢复远程片单的上次视频、播放进度和设置。
- Node 核心测试、语法检查、桌面与手机浏览器验收均通过。
