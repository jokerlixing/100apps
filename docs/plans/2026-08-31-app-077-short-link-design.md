# App 077 · ROUTE/77 短链聚合平台设计

## 产品边界

ROUTE/77 面向需要同时管理活动入口、二维码和渠道成效的小团队。页面只做一件事：让用户从一个真实目标地址创建可识别的短链，并立即看见这条“路线”的二维码和访问证据。

GitHub Pages 版本是完整的浏览器本地演示，短链与访问数据保存在当前浏览器；Node 版本提供 JSON 持久化、真实 `/r/:slug` 跳转和共享访问统计。界面必须明确区分两种模式，不把本地演示描述成云端服务。

## 方案选择

1. 通用 SaaS 仪表盘：熟悉但容易与任何后台产品互换。
2. 网络运维控制台：数据感强，但对非技术用户不够友好。
3. 城市线路调度台：用“入口—路由—到达”的语言解释短链，既有主题依据又容易操作。

采用方案 3。它将创建表单、短链、二维码和统计组织成一条可追踪线路，而不是堆叠无关卡片。

## 视觉系统

- `signal navy #071721`：页面与线路图底色
- `switchboard #102b36`：操作面板
- `ticket #f3efdf`：二维码票据和重要信息
- `route cyan #2bd5c4`：主线路与主要操作
- `transfer orange #ff7a4c`：换乘点、警告和当前选择
- `arrival green #a8df66`：在线、成功与增长
- 标题：`Arial Narrow` / `Franklin Gothic Medium`，形成交通标牌的紧凑字面
- 正文：`Segoe UI` / `Microsoft YaHei`
- 数据：`Cascadia Mono` / `Consolas`

记忆点是一条从目标地址穿过短链别名，最终抵达二维码票据的“线路轨迹”。其他装饰保持克制，信息密度由真实统计承担。

## 信息架构

```text
┌──────── rail ────────┬──────────── route console ────────────┐
│ ROUTE/77 / mode      │ headline + workspace actions          │
│ total / visits       ├─────────────────────┬──────────────────┤
│ online status        │ create route form   │ QR route ticket  │
│ privacy boundary     ├─────────────────────┴──────────────────┤
│                      │ route registry + search + filters      │
│                      ├─────────────────────┬──────────────────┤
│                      │ seven-day traffic   │ sources/devices  │
└──────────────────────┴─────────────────────┴──────────────────┘
```

手机端将侧栏折叠成状态条，创建器、票据、路线列表和统计按任务顺序纵向排列。

## 数据与错误处理

- URL 只允许 `http:` 与 `https:`，拒绝凭证和脚本协议。
- 别名只允许 3–32 位小写字母、数字和连字符，并阻止系统保留词和重复值。
- 本地模式使用版本化 localStorage；损坏数据回退到种子工作区。
- 服务模式限制 32 KiB JSON 请求体，串行原子写入 JSON 文件。
- 暂停路线返回 410；不存在路线返回 404；删除和清空操作需要二次确认。
- 二维码由 MIT `qrcode-generator` 在浏览器生成；依赖不可用时仍可复制短链，并显示明确降级说明。

## 验证

- 领域单测覆盖 URL、别名、重复、聚合、设备与来源分类。
- 服务单测覆盖静态白名单、创建、跳转计数、暂停、删除和重启持久化。
- 浏览器验收覆盖创建、复制、筛选、选择统计、刷新恢复、桌面/手机布局和运行时错误。
- 根追踪器测试验证 77 号名称、说明、公开链接与官方完成状态。
