# App 091 · 爬虫数据看板设计

## 产品边界

91 号项目命名为 **PULSEWATCH/91**，服务对象是需要盯住公开网页或接口变化的独立开发者和小团队。页面的唯一工作是：让用户在一次浏览中看清“哪些来源刚刚变化、变化在哪里、下一次何时检查”。它不是云端爬虫平台，也不会宣称网页关闭后仍能运行。GitHub Pages 版本只在当前标签页打开时定时轮询；真实 URL 必须允许浏览器跨域访问，登录页、验证码、反爬页面和需要服务端密钥的来源不在能力范围内。

内置四个演示来源，覆盖公告文本、价格、职位数量和服务状态。演示来源无需网络并会产生可重复的变化，方便首次打开立即验收。用户可以新增 CORS 可访问的 JSON 或文本 URL，选择 JSON 点路径、检查间隔和是否启用浏览器通知。所有来源、快照和事件只保存在 `localStorage`，支持 JSON 导出和校验后导入。

## 方案选择

考虑过三种实现：一是纯模拟看板，最稳定但缺少真实采集价值；二是配套 Node 服务端代理，能力更强但无法直接部署到 GitHub Pages，且会扩大 SSRF、安全和运维范围；三是浏览器直连 CORS 数据源并提供离线演示。选择第三种，它在挑战仓库的静态部署约束下仍有真实闭环，同时把跨域和后台调度限制写进产品界面。

## 视觉方向

视觉取材于港口水文观测站的纸质记录台，不使用常见的深色运维仪表盘。颜色令牌为：雾蓝纸 `#EAF1F4`、深海墨 `#16313A`、测量蓝 `#2E6D82`、变化珊瑚 `#E56B55`、警戒芥黄 `#D8A83E`、稳定苔绿 `#4D7768`。标题使用窄体 `Bahnschrift SemiCondensed`，正文使用 `Segoe UI`，时间、指纹与数据使用 `Cascadia Mono`。

桌面布局是左侧来源轨道、中间观测台、右侧事件电报码；移动端按“总览 → 来源 → 当前变化 → 事件”顺序堆叠。唯一醒目的视觉动作是一条“变化波形带”：每次采集是一根测量针，稳定为短蓝线，变化为高珊瑚线，失败为断开的芥黄线。它既是品牌签名，也是最近采集结果的真实编码。其余卡片保持低圆角、细刻度和克制阴影，避免装饰抢走数据层级。

## 架构与数据流

`monitor-core.js` 是零依赖 UMD 领域层，负责来源清洗、JSON 点路径提取、稳定序列化、FNV-1a 内容指纹、JSON/文本差异、调度时间和导入数据校验。`app.js` 负责 DOM、`fetch`、AbortController 超时、演示适配器、浏览器通知与本地持久化。领域层不访问 DOM 或网络，因此可用 `node:test` 完整验证。

一次检查的流程是：读取来源 → 在 10 秒超时内抓取或生成演示数据 → 按点路径提取 → 规范化快照 → 计算指纹与差异 → 写入最多 24 个采集点和 80 条事件 → 刷新波形、详情与统计 → 若发生变化且用户授权则发送系统通知。对同一来源使用运行锁，避免定时任务和手动操作重入。页面每 15 秒判断到期来源，但最小间隔为 1 分钟。

错误不会覆盖最后一次成功快照；事件记录具体原因，并给出“检查 URL 是否允许跨域访问”的修复提示。HTML 渲染只使用 `textContent` 或转义函数，不把远程内容直接拼进可执行标记。导入数据限制来源和历史数量，拒绝未知版本与不合法 URL。

## 验收标准

- 首次打开有四个可操作演示来源，点击“检查全部”后能看到变化、稳定和波形更新。
- 能新增同源或允许 CORS 的 JSON/文本 URL，并正确处理 JSON 点路径、超时、HTTP 错误和内容变化。
- 刷新页面后来源、快照、筛选和事件恢复；导出后清空再导入可恢复有效数据。
- 暂停来源后不参与自动检查；定时器不会对同一来源并发运行。
- 桌面 1440px 和手机 390px 无横向溢出，交互目标至少 44px，有可见焦点并尊重 reduced motion。
- 单元测试覆盖指纹稳定性、JSON/文本差异、路径提取、调度和导入清洗；浏览器验收覆盖首次变化、新增真实 HTTP 来源、持久化、暂停、导出及两个视口。
