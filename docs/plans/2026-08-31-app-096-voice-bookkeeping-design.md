# App 096 语音记账设计

## 产品边界

96 号项目沿用追踪器既定题目“语音记账”。成品命名为 **TALLY/96**，面向希望在付款后十秒内完成记录的个人用户。页面的单一任务是把一句自然语言变成一条用户看得懂、改得动、存得下的账目。

完整闭环为：说话或键入一句话 → 本地规则解析 → 在“解析小票”中校对 → 保存 → 月度汇总与流水即时更新。浏览器语音识别只是输入增强；不支持麦克风、拒绝权限或离线时，键盘输入和示例语句仍可完成全部功能。项目不把关键词匹配包装成 AI，也不把浏览器识别结果称为财务事实：金额缺失时禁止保存，分类、账户和日期都可以人工修正。

选择纯静态、本地优先方案。相比接入第三方模型，它在 GitHub Pages 上无需密钥、不会上传账本、失败面更小；相比只做录音按钮，它提供可测试的解析、校对、持久化、统计和导出闭环。当前版本不做多人账户、云同步、预算提醒或发票 OCR，以控制范围。

## 信息架构与数据流

页面分为四块：顶部状态栏；语音/文本收款台；可编辑解析小票；当月账本与统计。首次打开预置五条明确标注的演示账目，用户可一键清空。输入区提供三个可点击示例，便于无麦克风环境验收。保存后，流水按日期和创建时间倒序展示，可编辑、删除、按类型/分类筛选，并导出 CSV 或 JSON 备份。

每条记录包含 `id`、`type`、`amount`、`category`、`account`、`date`、`note`、`transcript`、`createdAt`、`updatedAt`。解析器识别阿拉伯数字、常见中文金额、收入/支出词、类别词、微信/支付宝/现金/银行卡和今天/昨天/前天/具体月日。解析结果附带识别提示与字段来源；金额不明确时返回可操作错误，不猜测数字。所有持久化数据经过长度、枚举、日期和金额校验，损坏缓存自动回退为空账本。

## 视觉方向

视觉取自便利店收银机和热敏小票，而不是通用金融仪表盘。色板：收银机深蓝 `#172B36`、热敏纸冷白 `#F4F6F1`、台面灰蓝 `#CAD8DA`、小票红 `#E34A32`、确认青 `#55BDB3`、提示黄 `#F3C64D`。标题使用 `Bahnschrift SemiCondensed` / `Arial Narrow`，正文使用 `Segoe UI` / `Microsoft YaHei`，金额与日期使用 `Cascadia Mono`。

桌面为 7:5 双列收款台，手机端纵向排列。唯一的视觉风险是“声纹走纸”：录音或载入文本时，输入区中的波形像热敏纸一样向下送出一张带锯齿边的可编辑小票。这一动作直接对应“说完即出账”，其余区域保持安静。按钮有可见焦点，手机触控高度不少于 44px，减少动态模式关闭走纸和波形动画。

## 验收策略

领域测试覆盖金额、中文数字、收支、分类、账户、相对日期、记录校验、汇总、筛选、CSV 转义和损坏缓存。浏览器冒烟测试覆盖键入/示例解析、校对保存、编辑删除、筛选、刷新恢复、CSV 下载、语音不可用降级、桌面和 390px 手机布局、键盘焦点、触控尺寸与运行时错误。桌面和手机截图作为 README 的可审计视觉证据。
