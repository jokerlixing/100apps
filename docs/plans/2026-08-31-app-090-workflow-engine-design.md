# App 090 · SWITCHYARD/90 自动化工作流引擎设计

## 产品边界

SWITCHYARD/90 面向想把重复操作组织成可靠流程、但不想先部署服务器的个人创作者与小团队。首版的单一任务是：让用户在浏览器内组合“触发器 → 条件 → 动作”，用一份可编辑的事件数据立即试跑，并从运行记录看清每一步发生了什么。

挑战清单要求 IFTTT 式自动化工作流。公开版本采用本地优先架构，工作流、运行记录与设置只保存在当前浏览器；手动触发、间隔触发和事件触发在页面打开时有效。通知、记录消息和设置字段会真实执行在本地上下文中；Webhook 动作在首版生成经过校验的请求预览，不会把用户数据静默发送到第三方。界面会明确说明页面关闭后调度停止，避免把静态演示伪装成云端常驻服务。

## 方案比较

1. **静态编排台 + 纯函数执行内核（采用）**：GitHub Pages 可直接运行，核心规则可单测，所有示例无需密钥。范围可控，同时完整展示编排、执行与审计闭环。
2. **Node 服务 + 定时任务进程**：能在页面关闭后继续执行并接收 Webhook，但 GitHub Pages 不能承载服务端，部署、鉴权和密钥存储会把首版扩大成基础设施项目。
3. **第三方自动化 API 客户端**：可接入真实服务，却依赖外部账号与密钥，难以让任何访问者立即检查核心体验。

## 架构与数据流

- `workflow-core.js` 提供工作流归一化、路径取值、条件判断、触发器匹配、动作执行、历史裁剪及备份校验。模块同时支持浏览器全局变量和 Node `require`。
- `app.js` 维护工作流集合、当前选择、事件载荷和运行记录；状态经版本化快照写入 `localStorage`。解析失败时回退到种子模板，损坏数据不会覆盖当前状态。
- 运行一次工作流时，先验证触发器，再依次执行全部条件；条件通过后按顺序执行动作。`setField` 会更新后续动作可见的上下文，`notification`、`log` 和 `webhookPreview` 生成结构化结果。
- 间隔触发器仅在页面打开且工作流启用时调度。每次启用、停用或修改间隔都会重建计时器，防止重复注册。
- 备份文件包含 schema 版本、导出时间、工作流和历史；导入前完整归一化并设置数量上限。

## 视觉系统

界面取材于铁路调度场，而不是通用 SaaS 仪表盘。主色为调度蓝 `#173B57`、图纸灰 `#DDE5E7`、信号橙 `#F26A3D`、通行青 `#17A79D`、警示黄 `#F4C95D` 与墨线 `#13232E`。标题使用 `Bahnschrift SemiCondensed` / `Arial Narrow`，正文使用 `Segoe UI` / `Microsoft YaHei`，事件与计数使用 `Cascadia Mono` / `Consolas`。

标志性元素是中央“转辙线路”：触发器、条件和动作不是漂浮卡片，而是固定在一条带方向的轨道上；运行时信号灯依次点亮，成功、跳过与失败拥有不同线路状态。其余界面保持冷静，圆角只用于信号灯和必要控件，不用大面积渐变或装饰性玻璃效果。

```text
┌ SWITCHYARD/90 ─ 调度状态 ───────────── [模板] [导入] [导出] ┐
├ 工作流名册 ─────┬──────────── 转辙线路 ────────────┬ 运行台 ┤
│ 搜索 / 状态      │  ○ 触发器 ──◇ 条件 ──□ 动作      │ 载荷   │
│ ● 每日简报       │  当前节点的配置与说明            │ 试运行 │
│ ○ 线索分流       │  + 条件 / + 动作                 │ 记录   │
│ + 新建工作流     │  页面开启时的调度边界            │ 详情   │
└─────────────────┴─────────────────────────────────┴────────┘
```

窄屏下三栏折成“名册 → 线路 → 运行台”的单列顺序；所有按钮拥有可见键盘焦点，状态不只依赖颜色，动画遵守 `prefers-reduced-motion`。

## 验证标准

- Node 单元测试覆盖路径取值、各类条件操作符、触发器匹配、动作上下文传递、跳过与失败、归一化、历史上限及导入边界。
- 静态检查确认资源存在、脚本语法有效、表单标签与对话框可访问。
- 浏览器烟雾覆盖模板加载、新建工作流、修改触发器与条件、成功试跑、条件跳过、启停、刷新持久化、导出以及 1440px / 390px 无横向溢出。
- 根追踪器登记 90 号最终名称、说明、GitHub Pages 地址与正式完成状态，并由测试锁定。
