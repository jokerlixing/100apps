# App 044 留言墙设计

## 产品定位

`POST/44 夜班邮局` 是一面无需登录、打开就能使用的本地留言墙。它面向想留下短句、心情或鼓励的人，页面的唯一核心任务是：让一条留言被投递、经过弹幕分拣带，并留在可以点赞的留言格中。

GitHub Pages 不能保存所有访客共享的数据，因此本项目明确采用本地优先模型：留言与点赞保存在当前浏览器，并通过 `BroadcastChannel` 同步同源标签页。首次访问提供一组示例留言，确保页面立刻呈现完整体验。

## 方案比较

1. **静态本地墙（采用）**：`localStorage + BroadcastChannel`，零配置、Pages 可用、离线可用；不同设备不会共享数据。
2. **托管数据库墙**：能真正跨设备共享，但需要密钥、鉴权、内容治理和额外平台配置。
3. **Node 实时墙**：数据协议可控，但重复 App 043 的部署成本，超出本项目的必要范围。

## 功能范围

- 发布 1–120 字纯文本留言，可填写 1–18 字署名并选择邮戳色。
- 两条分拣传送带循环播放留言弹幕，支持暂停与继续。
- 留言格支持点赞/取消点赞，显示发布时间和点赞数。
- 支持“全部 / 高赞 / 我的”筛选；高赞定义为至少 3 赞。
- 当前浏览器持久化，多个同源标签页实时合并发布与点赞。
- 最多保留 80 条留言；内置 6 条示例留言不计为用户所有。
- 所有用户内容只通过 `textContent` 渲染，不解释 HTML。

不做账号、评论回复、图片上传、公开审核、远程数据库和删除功能。

## 数据模型与规则

每条留言包含：`id`、`text`、`author`、`color`、`createdAt`、`likes`、`likedByMe`、`ownerId` 和 `seed`。

- ID 只允许字母、数字、下划线和连字符，长度 4–80。
- 时间必须为有限数值；文本清理控制字符并限制长度。
- 合并时按 ID 幂等，新版本以较新的 `updatedAt` 为准。
- 点赞操作是可逆的本地状态切换，点赞数永不小于 0。
- 存储损坏时回退到示例留言，不覆盖页面运行。
- `BroadcastChannel` 不可用时仍可在单标签页完整使用。

## 视觉系统

主题来自夜间邮局的分拣台，而不是常见的霓虹仪表盘或卡片后台。

- **邮政蓝** `#194B68`：主结构和标题。
- **夜班墨** `#15222D`：正文与深色区域。
- **信纸白** `#F7F1E3`：页面基底。
- **珊瑚邮戳** `#F26B5B`：主操作与点赞。
- **薄荷封蜡** `#A9D9C8`：辅助信息。
- **分拣黄** `#F2C14E`：焦点与运行状态。

标题使用宽重系统黑体形成邮袋标签感，正文使用清晰中文无衬线，编号与时间使用等宽字体。页面记忆点是两条带方向箭头的分拣传送带，明信片留言以不同速度横向经过，点赞后浮出一枚圆形邮戳。

## 页面结构

```text
┌ POST/44 ─ 房间说明 ─ 本地状态 ┐
│ 投进一句，等夜班邮局替你送达。 │
│ [署名] [邮戳色] [留言内容] [投递]│
├════ 分拣带 A：明信片弹幕 ═══════┤
├════ 分拣带 B：明信片弹幕 ═══════┤
│ 留言分拣格   [全部][高赞][我的] │
│ [留言] [留言] [留言]            │
└ 本地保存说明 ─ 统计 ─ 挑战编号 ┘
```

桌面端表单与说明并排，移动端改为单列；传送带始终保持横向裁切。键盘焦点清晰，系统偏好减少动画时自动停止弹幕并显示静态明信片。

## 验证标准

- 数据核心测试覆盖清洗、幂等合并、容量裁剪、点赞切换和筛选排序。
- 浏览器验证发布、纯文本安全、点赞、筛选、暂停、刷新恢复和跨标签同步。
- 检查 390px 响应式样式、减少动画规则、重复 ID、按钮类型与控制台错误。
- 根追踪器显示 44/100，并链接到 GitHub Pages 页面。
