# App 086 · CLI 天气工具设计

## 产品定位

86 号项目是一个可直接在 Windows、macOS 与 Linux 终端运行的天气查询工具。用户输入城市名，就能在一次命令中看到当前体感、湿度、风速、降水和未来数日预报，并由天气代码生成对应的 ASCII 天气图。工具面向快速查询，不引入账户、配置文件、数据库或 API Key；默认中文输出，同时提供英文、华氏温度和机器可读 JSON，方便个人终端使用及脚本集成。

选择零运行时依赖的 Node.js 18+ 实现。相较 Python 方案，这与仓库已有 Node 工具的运行方式一致；相较 shell 脚本，它能稳定处理跨平台参数、Unicode 城市名、HTTP 超时与结构化 JSON。数据来自 Open-Meteo：先用 Geocoding API 将城市解析为经纬度与时区，再用 Forecast API 查询当前天气和逐日聚合。服务端返回的 WMO 天气码只在本地映射为文案与图形，不把展示逻辑耦合进网络层。

## 架构与数据流

入口 `bin/weather.js` 只负责启动进程，`src/args.js` 解析并校验位置、预报天数、单位、语言与输出模式。`src/api.js` 构造 URL、处理超时、HTTP 状态、API 错误包络及空搜索结果；所有网络函数接收可注入的 `fetch`，使测试不访问公网。`src/weather-codes.js` 维护 WMO 代码到晴、云、雾、雨、雪、雷暴的归类、双语文本和 ASCII 图。`src/format.js` 将标准化数据渲染成终端卡片或 JSON；`src/cli.js` 编排完整流程并把用户输入错误与网络错误转换成清晰退出码。

命令默认显示三天预报，允许 `--days 1..7`、`--unit c|f`、`--lang zh|en`、`--json` 与 `--no-color`。帮助和版本查询不触发网络。彩色输出只在交互终端启用，并尊重 `NO_COLOR`，因此重定向到文件或测试快照时不会混入 ANSI 控制码。城市会显示 API 实际解析出的行政区和国家，降低同名地点造成的误解。

## 失败处理与验证

参数错误返回退出码 2，并附一条可执行示例；位置无匹配、超时、非 2xx 响应、无效 JSON 或缺少天气字段返回退出码 1，不输出堆栈。JSON 模式在成功时输出稳定的规范化结构，适合作为其他脚本输入；错误仍写入 stderr，避免污染 stdout。服务不可达时不会伪造天气，也不会缓存过期结果。

自动化测试覆盖参数边界、URL 编码、中英文天气码、风向、终端渲染、JSON 结构、无匹配城市、超时/API 错误和 CLI 退出码。交付前还会运行语法检查、无网络 mock 集成测试、一次真实城市查询、`npm pack --dry-run` 与根追踪器测试。GitHub Pages 只能展示项目文件和 README，CLI 的官方入口因此是仓库目录链接；追踪器仍登记该可访问 URL并标记正式完成。
