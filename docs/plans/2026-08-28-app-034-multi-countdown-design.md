# App #034 多任务倒计时设计

## 目标

为需要同时关注多项短时任务的人提供一个零配置、本地运行的并行倒计时台。单个页面完成创建、运行、批量控制、到点提醒与刷新恢复，不引入账号、后端或网络依赖。

## 方案比较

### A. 多个独立 `setInterval`（不采用）

每个计时器自行每秒减一。实现直观，但标签页进入后台后会降频，刷新后也难以恢复准确时间；计时器越多，调度越分散。

### B. 单一节拍器 + 绝对截止时间（采用）

所有运行中任务保存 `endAt`，页面用一个节拍器根据 `Date.now()` 计算剩余值。暂停时保存差值，刷新时重新比较截止时间。模型简单、准确，也方便批量暂停和恢复。

### C. Web Worker 计时（暂不采用）

后台节拍更稳定，但本项目只需要正确显示真实剩余时间，并不依赖每秒回调一定执行。绝对截止时间已经解决漂移问题，引入 Worker 会增加不必要的复杂度。

## 功能边界

- 默认提供四条待命示例任务
- 新建任务包含名称、时分秒和五种赛道颜色
- 每条任务支持开始/暂停、复位、加一分钟和二次确认删除
- 总控支持继续全部、暂停全部、全部复位
- 完成时更新状态、显示横幅、ARIA 播报并播放可关闭的三音提示
- 保存任务与声音偏好，运行中任务刷新后按真实时间恢复
- 不申请系统通知权限，不承诺浏览器关闭后仍能提醒

## 数据与状态

```text
timers[]
  ├─ paused: remainingMs 为暂停时剩余值
  ├─ running: endAt 为绝对截止时间
  └─ done: remainingMs = 0, endAt = null

单一 tick
  ├─ 更新当前时间
  ├─ 计算每条 running 的 endAt - now
  └─ 到点时只触发一次完成状态与提醒
```

localStorage 只在新建或状态变化时写入。加载时清洗标题、时长、状态和主题字段；损坏条目会被忽略。

## 视觉系统

- `#DFF4F6` 冰蓝工作台：主背景
- `#F8FBFA` 计时纸面：卡片和输入区
- `#2A1743` 深紫墨色：边框、数字与结构
- `#3166F5` 电子蓝：主要赛道与动作
- `#FF5A36` 撞线橙：完成警报
- `#D9FF63` 信号黄绿：运行状态与新建动作

显示字体使用 Arial Black / 微软雅黑，读时与设备标签使用 Consolas。签名元素是每张卡片横跨二十格的赛道进度条与移动标记，它把“剩余时间”直接转化为比赛距离。

## 验证重点

- 两个以上计时器能独立运行、暂停和复位
- 批量控制只影响符合条件的任务
- 秒级任务到点后只提醒一次
- 运行中刷新后剩余时间继续减少而非重置
- 新建 0 秒任务得到明确错误
- localStorage 损坏时页面仍可加载
- 桌面、平板和手机无横向溢出，移动端读时不截断
