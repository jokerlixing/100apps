# App 050 · BEAM/50 局域网文件快传设计

## 产品目标

做一个无需账号、无需上传网盘的浏览器文件快传站。两台设备打开页面后，通过扫描二维码或粘贴连接文本交换 WebRTC 握手信息，随后文件在设备之间点对点传输。

## 范围取舍

- 使用 WebRTC DataChannel 传输文件；静态页面可部署到 GitHub Pages，文件内容不经过应用服务器。
- 使用二维码或连接文本完成双向握手，不建设信令服务器，也不生成需要后台维护的短码。
- 提供发送与接收两种角色，一次会话可顺序传输多个文件，总大小上限 200 MB。
- 接收端在浏览器内暂存文件，完成后由用户逐个保存；不做账号、历史云同步和断点续传。
- 配置公共 STUN 仅用于发现网络路径，不配置 TURN 中继；同一局域网成功率优先，复杂企业网络可能阻止连接。

## 核心体验

1. 首页选择“发送文件”或“接收文件”。
2. 发送端选择文件后生成邀请二维码；接收端扫码或粘贴邀请文本。
3. 接收端生成回应二维码；发送端再次扫码或粘贴回应文本。
4. 通道建立后，发送端按队列逐个传输；双方看到文件名、总量、实时速度和整体进度。
5. 接收完成的文件显示“保存文件”，会话可继续发送下一批或安全断开。

## 视觉方向

主题名为「BEAM/50 本地分拣线」。视觉取材于快递面单、机场行李标签和仓库传送带，而非通用深色科技面板：

- 雾白纸面配物流蓝、警示橙、荧光青绿和深墨色，背景使用稀疏坐标网格。
- 标题采用窄体工业字形，正文使用清晰的中文无衬线，连接文本与速度使用等宽字。
- 首屏中央是一条连接两台设备的“包裹轨道”；连接后文件块沿轨道移动，状态变化能一眼读懂。
- 操作区像两联运输面单，真实的步骤编号只用于握手顺序；二维码位于可撕取的配对票据中。
- 桌面端为轨道加双栏工作台，移动端折叠为单列；键盘焦点和 reduced-motion 均有明确支持。

## 数据与协议

- 握手文本格式为 `beam50.v1.<payload>`；会话描述使用浏览器原生 CompressionStream 压缩后以 Base64URL 编码，不支持压缩时回退到原始 JSON。
- 邀请载荷只包含协议版本、角色和 RTCSessionDescription，不包含文件内容。
- DataChannel 使用可靠有序模式。字符串消息传输 `hello`、`file-meta`、`file-end`、`batch-end` 和 `error`，二进制消息传输 32 KiB 文件分片。
- 发送端依据 `bufferedAmount` 进行背压控制，避免一次把大文件全部写入内存队列。
- 接收端验证元数据、分片累计长度和 200 MB 会话上限，文件名移除路径字符后再用于下载。

## 错误与边界

- 非法、过期或角色不匹配的连接文本显示页面内错误，不调用原生 alert。
- 二维码库或摄像头不可用时始终保留复制、粘贴和上传二维码图片的路径。
- 用户拒绝摄像头、扫码超时、ICE 失败、通道中断和文件校验失败都有可恢复提示。
- 页面关闭、刷新或主动断开会终止当前传输；界面明确提示传输期间保持页面打开。
- 接收端不会自动下载文件，避免多文件下载被浏览器拦截。

## 可验证标准

- Node 单元测试覆盖文件队列校验、文件名净化、字节与速度格式、进度和握手载荷编解码。
- 两个浏览器页面可通过复制连接文本完成 WebRTC 建连，并传输文本文件且内容一致。
- 二维码生成、摄像头/图片扫码入口、复制粘贴回退路径均可用。
- 1440×900 与 390×844 下无横向溢出，主要流程可用键盘完成，控制台无应用错误。
