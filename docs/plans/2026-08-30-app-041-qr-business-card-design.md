# App #041 STAMP/41 二维码名片设计说明

## 产品定位

面向活动参会者、自由职业者和需要快速交换联系方式的创作者。页面只有一个核心任务：把一组联系人信息制成兼容手机通讯录的 vCard，再用二维码和 VCF 文件让对方一次完成保存。

## 方案比较

1. **通用联系人表单**：操作最熟悉，但容易退化为缺少记忆点的后台录入页。
2. **社交个人主页**：展示感更强，却会把注意力从“扫码保存联系人”带向链接聚合。
3. **通讯录制版室（采用）**：把信息录入、名片预览、二维码生成和文件下载串成一次套色制版流程，既能突出工具价值，也有清晰的视觉主题。

## 视觉系统

- 纸张桃粉 #ffded5：页面底纸与大面积背景
- 森林墨 #173f38：正文、边框、二维码与主按钮
- 套色蓝 #3157e6：链接、焦点与第二印版
- 登记红 #ef563f：必填、错误与二维码印章
- 日光黄 #ffd45c：编号、提示和套色标记
- 铅白 #fffaf4：表单、卡片与二维码纸面
- 展示字：Arial Black / Microsoft YaHei，用于标题、编号和主操作
- 正文字：Segoe UI / Microsoft YaHei，用于表单与说明
- 数据字：Cascadia Mono / Consolas，用于 vCard、字节数和制版状态

## 标志性元素

右侧名片是一张带裁切线和套色圆点的“身份印版”。姓名和二维码使用轻微错位的蓝红套色影子；二维码生成后，红色“可保存联系人”印章落在纸边。页面背景仅使用细网点和登记线，不依赖插图或外部图片。

## vCard 与二维码模型

- 使用兼容性更广的 vCard 3.0，输出 `N`、`FN`、`ORG`、`TITLE`、`TEL`、`EMAIL`、`URL`、`ADR` 与 `NOTE`
- 姓名必填，电话和邮箱至少填写一项；邮箱、电话和网址分别做格式校验与规范化
- 反斜线、分号、逗号和换行按 vCard 文本规则转义，换行统一为 CRLF
- 二维码使用 UTF-8 字节生成，容错级别 M，自动选择版本；四模块静区和高对比色固定保留
- 当二维码容量不足时阻止导出，指出需要精简的字段，不生成不可扫描的假结果

## 状态与隐私

- 联系人字段保存在当前浏览器的 localStorage 草稿中，用户可随时清空
- 数据不会发送到服务器；二维码、VCF 与 PNG 都在浏览器本地生成
- QR 生成失败、缺失必填、格式错误和依赖加载失败分别展示可理解的状态
- VCF 与 PNG 只在用户主动点击时下载；复制 vCard 失败时提供明确回退提示

## 验收标准

- 测试资料可一次装入并生成完整中文 UTF-8 vCard 与二维码
- 编辑任一字段后，名片预览、vCard 字节数和二维码同步更新
- 姓名为空、电话邮箱均空、邮箱非法或网址非法时，错误与焦点定位正确
- 下载 VCF 的 MIME、文件名和 CRLF 内容正确，下载 PNG 有四模块静区
- 复制按钮复制与预览一致的 vCard 文本
- 草稿刷新恢复，清空需二次确认并清除 localStorage
- 桌面与 390px 手机布局无横向溢出，键盘焦点清楚并尊重减少动态效果
- 追踪器显示 41/100，第 041 项链接和完成态正确
