# App 083 · TACK/83 桌面便签设计

## 产品边界

TACK/83 面向需要在编码、开会和查资料之间快速记下一句话的知识工作者。它的单一任务是：让一张正在编辑的便签保持在桌面最前方，同时把其他便签可靠地保存在本机。

挑战清单要求 Electron 桌面端与置顶便签。项目同时保留一个 GitHub Pages 网页演示；网页端拥有完整的便签增删改查、搜索、筛选、归档、导入导出和紧凑界面，但会诚实标注浏览器不能控制操作系统窗口层级。Electron 端通过隔离的 preload API 增加原生始终置顶、窗口尺寸切换和窗口状态恢复，不把 Node 权限暴露给页面。

## 方案比较

1. **静态核心 + Electron 包装层（采用）**：核心数据、界面和本地存储在网页与桌面端共用；Electron 只处理窗口能力。公开演示可直接访问，桌面能力也真实可用，且最容易测试。
2. **纯 Electron 多窗口便签**：每张便签都成为独立窗口，更接近系统便签，但窗口生命周期、跨窗口同步和打包显著扩大首版范围，也失去 GitHub Pages 演示。
3. **PWA 安装版**：部署简单且可离线，但标准浏览器 API 无法可靠实现始终置顶，不满足题目最关键的桌面能力。

## 体验与数据流

- 左侧“便签匣”提供搜索与全部、置顶、已归档筛选；右侧是当前便签的编辑台。
- 新建、复制、置顶、换色、归档和删除都立即写入 `localStorage`；正文输入短暂防抖后刷新列表摘要。
- 首次打开生成三张入门便签。所有用户文本只通过 `textContent` 或表单值渲染，导入数据先经核心模块归一化。
- JSON 备份包含版本号、导出时间和便签数组；损坏或结构错误的文件不会覆盖现有数据。
- Electron 主进程将窗口位置、尺寸、紧凑模式和置顶状态写入 `userData/window-state.json`。页面只能调用白名单 IPC，不可访问文件系统或任意 Electron API。

## 视觉系统

- **冷轧蓝** `#18324A`：窗口骨架、标题与当前状态。
- **工作台雾灰** `#E8ECE9`：应用背景，像金属办公桌而非通用卡片画布。
- **索引黄** `#FFD45C`：默认便签和主操作。
- **校对珊瑚** `#EF6A5B`：删除、提醒与高优先色。
- **标签青** `#68C5B5`：完成感与辅助色。
- **铅字黑** `#17212B`：正文与结构边线。

标题使用 `Bahnschrift SemiCondensed` / `Arial Narrow`，正文使用 `Segoe UI` / `Microsoft YaHei`，时间与计数使用 `Cascadia Mono` / `Consolas`。页面的标志性元素是一条横贯编辑区的金属“桌轨”：当前便签像索引纸一样被夹在轨道下，启用桌面置顶后图钉会亮起。其余装饰保持克制。

## 布局草图

```text
┌ TACK/83 ─ 桌面快记台 ───────── [始终置顶] [紧凑模式] ┐
├──────────────┬────────────────────────────────────────┤
│ 搜索便签     │  金属桌轨 · 当前状态 · 自动保存       │
│ 全部 置顶 归档│  ┌──────────────────────────────────┐ │
│ ┌便签摘要──┐ │  │ 标题 / 颜色 / 置顶 / 复制        │ │
│ ├便签摘要──┤ │  │                                  │ │
│ └便签摘要──┘ │  │ 正文编辑                         │ │
│ + 新建便签   │  │                                  │ │
│ 导入 / 导出  │  └──────────────────────────────────┘ │
└──────────────┴────────────────────────────────────────┘
```

宽度低于 780px 时，便签匣变成顶部横向列表；Electron 紧凑模式只保留当前便签和必要动作。键盘焦点清晰，动画只用于便签切换与图钉状态，并遵守 `prefers-reduced-motion`。

## 验证标准

- Node 单元测试覆盖创建、更新、复制、搜索、筛选排序、归档以及备份导入边界。
- 静态检查确认页面资源、可访问标签、Electron 安全选项和 IPC 白名单。
- 浏览器烟雾测试覆盖首屏、新建、编辑、搜索、置顶、紧凑模式、刷新恢复和导出。
- Electron 启动检查确认应用创建窗口且无主进程异常；人工运行命令记录在 README。
