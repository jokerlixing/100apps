# App 067 AI 菜谱推荐设计

## 产品边界与用户路径

67 号应用命名为 **PANTRY/67**，服务于“冰箱里有一些食材，但今晚不知道做什么”的独居者与小家庭。页面只承担一条主路径：录入现有食材与用餐限制，生成三道可执行的候选菜，选中一道后得到明确用量、缺少食材、替代建议和逐步做法。用户无需账号或 API Key 就能使用内置推荐引擎；服务器配置 AI 提供商后，应用会请求更有变化的生成式方案。AI 不可用、超时或返回异常数据时，界面保留本地结果并明确标注“本地配餐”，不把规则匹配伪装成在线 AI。

输入台支持常用食材快捷磁贴、中文顿号/逗号批量粘贴、人数、最长耗时、饮食偏好、忌口和菜系。结果区首先解释“为什么推荐”，随后给出已有/缺少食材、估算用量、步骤、时间和难度。缺少食材可以加入采购单并一键复制；收藏与最近一次输入只写入 localStorage。营养数字明确标注为估算值，过敏原限制采用保守过滤，并提醒严重过敏用户自行核对商品标签。核心闭环是“清点冰箱 → 得到方案 → 补齐采购 → 开始烹饪”，不加入账号、社交、图片生成或库存保质期管理。

## 架构、数据流与失败处理

`recipe-core.js` 是零依赖 UMD 模块，负责食材别名归一化、批量解析、忌口过滤、候选打分、缺料与替代项计算、推荐排序，以及 AI 响应的字段清洗。浏览器控制器维护输入、推荐、当前菜谱、收藏和采购单状态；它先同步生成可信的本地候选，再向同源 `/api/recommend` 请求增强结果，成功后替换票据，失败则安静保留本地候选并显示可理解的状态。这样 GitHub Pages 上的静态版本完整可用，Node 服务模式则提供真实 AI 能力。

`server.js` 使用 Node 内置 HTTP、Fetch 与文件 API，不引入运行时依赖。密钥只从 `AI_API_KEY` 读取，模型和兼容端点由 `AI_MODEL`、`AI_BASE_URL` 配置。接口限制 JSON 请求体大小和字段数量，把整理后的约束发送给 OpenAI-compatible Chat Completions 服务，再使用核心模块校验结果；上游错误只返回稳定的 503，不泄露密钥或原始响应。服务器同时提供静态文件，便于一次命令运行完整模式。

单元测试覆盖别名、分隔符、去重、饮食/忌口/耗时过滤、打分稳定性、空结果放宽策略、AI 数据清洗和恶意字段。服务测试覆盖无密钥降级、错误请求、上游成功与失败、静态入口和路径穿越。浏览器冒烟测试覆盖批量输入、生成三张票据、选择菜谱、采购单、收藏恢复、AI 失败降级、1440px 桌面与 390px 手机、横向溢出、键盘焦点以及控制台异常。

## 视觉系统与响应式布局

视觉来自餐厅后厨的备餐台，而不是常见 AI 仪表盘。色板为台面银 `#D8DEDA`、器械黑 `#18201E`、搪瓷绿 `#2F6B52`、番茄红 `#E4572E`、蛋黄黄 `#F3BE3E`、票据白 `#FFFDF5`。标题使用窄体粗黑的 `Arial Narrow` / `Microsoft YaHei`，正文使用 `Segoe UI`，时间、克数和状态使用 `Cascadia Mono`。结构标签只表达真实厨房流程：`备料台`、`出单口`、`采购夹`，避免无意义编号。

桌面端左侧是带刻度和铆钉的不锈钢食材台，右侧是一台固定的黑色出单机。输入食材变成略有角度差异的彩色磁贴；点击“开始配餐”后，唯一主动画是一张带锯齿边的长票据从出单槽向下滑出，其他控件不做漂浮或发光。结果票据上方并列三张窄订单签，选中后下方展开完整做法。移动端把出单机移到备料台下方，磁贴和快捷食材可横向换行，按钮与复选框触控区不小于 44px。`prefers-reduced-motion` 下取消打印位移动画；高对比焦点环、语义化状态播报和明确错误文案保证键盘与读屏器可用。
