# App 063 AI 写作助手设计说明

## 产品定位

`MARGIN/63 文字手术台` 面向需要快速改稿的中文内容创作者、运营和知识工作者。页面的唯一核心任务是：让用户把一段原稿变成可控、可比较、可继续编辑的修订稿，而不是与聊天机器人来回对话。

完成范围包括润色、扩写、翻译和风格改写。每次生成都保留原稿，显示前后字数、变化比例和逐词差异；用户可以复制、下载、把结果送回原稿继续加工，也可以从本地历史恢复最近八次记录。

## 方案比较

1. 纯本地规则引擎：上线即用且无密钥风险，但无法诚实地覆盖通用翻译和高质量改写。
2. 只接真实 LLM API：能力完整，但 GitHub Pages 首次打开是不可用状态，且容易诱导用户长期保存密钥。
3. 安全 BYOK + 本地演示：真实生成使用用户自己的 OpenAI-compatible 接口；未配置接口时用明确标记的本地演示验证完整交互。该方案兼顾可访问性、诚实边界和真实 AI 能力，因此采用。

## 信息架构

桌面端是一个校对工作台，而不是聊天界面：

```text
┌ MARGIN/63 ─ 状态 ─ 接口设置 ─ 历史 ┐
│ 改写器械 │ 原稿 MANUSCRIPT │ 修订稿 REVISION │
│ 润色     │ 输入与约束       ╎ 流式输出与差异  │
│ 扩写     │ 字数/语气/保留词 ╎ 复制/下载/接续  │
│ 翻译     │                  ╎                │
│ 改风格   │                  ╎                │
└─────────── 运行状态与安全说明 ─────────┘
```

手机端按“模式 → 原稿 → 运行 → 修订稿”顺序堆叠。原稿和修订稿始终是两个独立区域，避免生成内容覆盖用户输入。

## AI 与数据流

真实模式由用户填写接口地址、模型名和可选 API Key。地址与模型可以保存在 `localStorage`；API Key 只保存在当前页面的 JavaScript 内存，刷新即清除，也不会进入历史、日志或下载文件。

请求采用 OpenAI-compatible Chat Completions 形状：`model`、`messages`、`stream`。响应兼容 SSE `choices[].delta.content`、普通 JSON `choices[].message.content`，并容忍 `output_text` 或 `delta` 文本字段。用户可随时中止流式生成。

没有有效接口设置时进入本地演示。演示只用于验证润色、扩写、翻译、风格切换、差异和导出流程；界面持续显示“本地演示”，绝不把规则结果冒充真实模型输出。

## 视觉系统

- 手术纸 `#F3F7F6`：主背景，保持冷静而非常见暖米色。
- 深海墨 `#102A43`：正文与结构线。
- 电蓝 `#3155F5`：主要动作与运行状态。
- 校对橙 `#FF6846`：删除、警告和手写批注。
- 证明绿 `#C8F169`：新增内容与成功状态。
- 钢尺灰 `#A9BBC8`：分隔线和次要信息。
- 标题使用 `Arial Black` / `Microsoft YaHei`，正文使用 `Palatino Linotype` / `STSong`，数据与标签使用 `Consolas`。

签名元素是横跨原稿与修订稿的“修订缝线”：待机时是刻度尺，生成时成为单一的进度动效，完成后成为差异图例。其余装饰保持克制，不使用泛化 AI 渐变、玻璃卡片或聊天气泡。

## 状态、错误与无障碍

- 空白原稿、接口缺项、HTTP 错误、空响应和中止分别给出可执行的提示。
- 真实生成开始后主按钮切换为“停止生成”；原稿不会被锁死或覆盖。
- 全部按钮有可见键盘焦点；模式选择使用 `aria-pressed`，状态更新使用 `aria-live`。
- 390px 宽度不横向溢出；点击目标不小于 44px；尊重 `prefers-reduced-motion`。
- 历史只保存输入、输出、模式和非敏感选项，最多八条；提供一键清空。

## 验证策略

核心单元测试覆盖文本计数、提示构建、接口校验、SSE 分帧、响应文本提取、差异算法和四种本地演示模式。CDP 浏览器冒烟测试覆盖桌面与手机布局、四种模式切换、本地生成、停止/错误状态、差异渲染、历史持久化、复制替代路径、接口设置不持久化密钥，以及运行时错误和横向溢出。
