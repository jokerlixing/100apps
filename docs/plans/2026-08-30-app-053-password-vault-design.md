# App 053 · LOCKBOX/53 本地密码管理器设计

## 产品边界

LOCKBOX/53 面向希望在单台设备上整理少量账号、又不愿把秘密交给云服务的个人用户。页面只做一件事：用一个主密码解锁本地保险箱，并在锁定状态下让浏览器里只剩不可读的密文。它不注册账号、不连接服务器、不提供跨设备同步，也不尝试替代浏览器扩展的自动填充。

首轮功能包括创建与解锁保险箱、账号条目增删改查、关键词搜索、密码显示与复制、安全随机密码生成、手动/自动锁定，以及加密备份导入导出。主密码无法找回；重置保险箱会永久删除本机密文，因此界面必须在创建、导入和删除时明确说明后果。

## 安全模型

- 主密码只在当前解锁会话的内存中参与密钥派生，不写入 `localStorage`、日志、URL 或导出文件。
- 使用 Web Crypto 原生实现：PBKDF2-HMAC-SHA-256（600,000 次、16 字节随机盐）派生不可导出的 256 位 AES-GCM 密钥。
- 每次保存整个保险箱时生成新的 12 字节随机 IV；AES-GCM 同时保证机密性和完整性，版本字符串作为附加认证数据。
- `localStorage` 只保存带版本、KDF 参数、盐、IV 与密文的信封。错误主密码、密文损坏或认证数据变化都会导致解密失败。
- 加密备份导入前先做严格结构校验并用输入的主密码试解密；只有成功后才替换本机保险箱。
- 页面无第三方脚本、字体或网络请求，并通过 CSP 禁止连接外部地址，减少供应链和 XSS 暴露面。

这个模型保护静态存储泄露，但不能抵御已经控制页面脚本、浏览器扩展、操作系统、键盘记录或剪贴板历史的攻击。锁定时会丢弃当前 `CryptoKey` 与明文状态，但 JavaScript 无法保证立即擦除引擎内部的所有内存副本。README 和页面帮助区都要诚实说明这些边界。

## 信息架构与交互

首次访问显示“封存新保险箱”票据，要求主密码至少 12 个字符并二次确认。已有保险箱时显示机械锁盘式解锁区，同时提供导入备份入口。解锁后的桌面布局分成三个区域：左侧是搜索与账号索引，中间是当前条目的编辑工单，右侧是密码铸造台和保险箱状态。移动端按“索引—工单—生成器”顺序纵向排列。

账号字段控制在标题、用户名、密码、网址和备注五项。保存、删除、复制、显示密码、生成密码等动作都有可读状态反馈；错误信息说明下一步，而不是只给“失败”。编辑区默认遮挡密码，网址只在 `http:` 或 `https:` 时显示为可打开链接。空保险箱引导用户创建第一条记录，搜索无结果则提供清除搜索按钮。

默认 5 分钟无操作自动锁定；用户可在 1、5、15、30 分钟之间调整。计时器只在解锁期间运行，键盘、指针和触摸活动会重置计时。页面进入后台不会立刻锁定，但超时后返回页面会立即检查并锁定。所有敏感操作都支持键盘，焦点样式清晰，并尊重 `prefers-reduced-motion`。

## 视觉系统

设计主题来自锁匠的钥匙切割工作台，而不是常见的黑色“黑客终端”。页面背景是冷灰蓝色金属台面，账号索引像挂在号码轨道上的钥匙牌，编辑表单像夹在工作台中央的维修工单；锁定时出现一枚可轻微转动的同心锁盘。这枚锁盘是唯一的视觉风险点，其余组件保持克制。

- 工作台蓝 `#DCEAF0`：页面底板与空气感
- 枪灰 `#172630`：正文、结构线与主按钮
- 钥匙黄 `#F2C14E`：当前选择、生成动作与焦点
- 氧化铜 `#3E9D89`：已加密、已保存与安全状态
- 封条红 `#D9574F`：危险操作与校验错误
- 工单白 `#F8F6EF`：表单、票据与列表卡
- 展示字：`Bahnschrift Condensed` / `Arial Narrow`，用于锁盘、标题和账号编号
- 正文字：`Segoe UI` / `Microsoft YaHei`，用于表单与帮助
- 数据字：`Cascadia Mono` / `Consolas`，用于密码、计时与加密参数

结构线、编号和冲孔都对应真实的锁匠工单语义，不作为随意装饰。动效集中在解锁瞬间的锁舌滑动与面板展开；其余 hover 只做轻微位移和颜色变化。

## 数据与错误流程

业务数据结构为 `{ entries, createdAt, updatedAt }`，每条记录包含随机 ID、五个用户字段和创建/更新时间。保存时先规范化长度与空白，再生成新 IV 并重新加密整个对象，最后一次性替换本地信封。条目数限制为 200，单字段与备份大小也设置上限，防止异常输入拖垮页面。

解锁失败统一显示“主密码不正确或保险箱已损坏”，避免对密文内部状态作错误推断。浏览器缺少安全上下文或 Web Crypto 时阻止创建/解锁，并说明必须通过 HTTPS 或 localhost 打开。`localStorage` 写入失败时保留当前内存状态、禁止声称已保存，并提示立即导出备份。剪贴板失败时保持秘密遮挡，不把密码回填到普通提示文本中。

## 验证重点

- 相同主密码与数据的两次保存必须产生不同盐或 IV；错误主密码、篡改密文和非法信封必须拒绝。
- 生成器使用 `crypto.getRandomValues`，满足长度、字符组选项和必含类别约束，不使用 `Math.random`。
- 首次创建、锁定重开、增删改查、搜索、复制、生成、自动锁、导出和导入形成完整可恢复流程。
- 1280px、768px 和 390px 下无横向滚动；锁定页与解锁页均检查键盘焦点、错误反馈和减少动态效果。
- DevTools 控制台无错误，页面发出的网络请求为零，`localStorage` 中搜索不到任一测试明文。
