# App 074 · 在线协同文档设计

## 产品边界

App #074 定名为 **GALLEY/74 校样室**，服务于需要快速共同修订一份短文档的小团队。页面的单一任务是：打开一个房间链接后，参与者可以编辑同一份文档、看到在线成员、留下可解决的批注，并在误改后恢复历史版本。GitHub Pages 版本无需账号或密钥，使用 `BroadcastChannel` 在同一浏览器的多个标签页间实时协作并保存到本地；仓库同时提供 Node.js WebSocket 服务，启动后支持局域网或部署后的跨设备协作。静态模式必须明确标注“本机协作”，不把多标签页同步冒充成互联网服务。

在三种方案中，选择“静态优先 + 可选 WebSocket”：纯云数据库方案需要用户密钥，纯静态方案不能覆盖真正的跨设备场景，而双通道方案延续本仓库 #042/#043 的部署方式，并在任何网络条件下都保留可验收的核心流程。同步采用受版本号约束的整份文档快照，而不是引入 CRDT；它适合本挑战的短文档和小团队，但不声称能无损合并同一段落的并发输入。

## 信息架构与视觉系统

界面来自“编辑部校样桌”的真实物件：左侧是文档抽屉，中间是一张可编辑校样纸，右侧是批注和版本轨道。桌面宽屏为三栏，窄屏保留编辑纸，把抽屉与批注轨道变成可切换面板。顶部只放房间、连接状态、成员和分享；格式工具贴在纸张上沿，避免做成常见数据后台。

```text
┌ room / connection / members / share ─────────────────────┐
│ document drawer │ formatting + paper      │ margin notes  │
│ new / rename    │ title                   │ comments       │
│ recent docs     │ rich content            │ versions       │
│                 │ words / save state      │ restore        │
└───────────────────────────────────────────────────────────┘
```

色彩使用 Desk `#D9E1E8`、Ink `#20242A`、Paper `#FFFDF6`、Proof red `#D64A3A`、Editor blue `#2457D6` 与 Marker yellow `#F1C84B`。正文采用宋体系，产品控件使用清晰的无衬线体，房间号和时间使用等宽体。唯一的视觉冒险是右侧“红铅笔批注轨道”：批注卡通过校样线与纸张边缘相连，其余元素保持克制。动画仅用于连接灯、保存状态和面板进入，并尊重 `prefers-reduced-motion`。

## 数据、错误与验证

文档状态包含 `title`、经过客户端白名单清洗的 HTML、批注数组、版本号、更新时间和更新者。客户端对输入做 240ms 防抖；WebSocket 在线时以服务端版本为准，离线或静态托管时用房间级 `localStorage` 与 `BroadcastChannel`。服务端限制房间人数、标题/正文/批注长度、消息大小与更新频率，拒绝旧版本覆盖并回发权威快照。远端姓名、状态和批注正文都只通过 `textContent` 渲染；文档 HTML 仅允许编辑器生成的基础排版标签和安全属性。

空房间用内置欢迎稿引导第一次编辑。断线时显示可操作的“已切换本机协作”，导入失败时解释所需 JSON 结构，恢复历史前需二次确认。验证分三层：纯函数单元测试覆盖房间号、输入裁剪、版本冲突和文档校验；真实 WebSocket 测试覆盖房间隔离、快照、并发冲突、批注与成员；浏览器烟测覆盖编辑、第二标签页同步、批注、版本恢复、导出和响应式布局。根追踪器只在应用验证完成后更新，并在同步最新 `origin/main` 后加入 #074 的正式名称、说明、部署链接和完成状态。
