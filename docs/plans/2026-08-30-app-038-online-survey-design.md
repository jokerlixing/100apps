# App #038 PULSE/38 在线问卷系统设计说明

## 产品定位

面向工作坊主持人、产品研究者和小团队。页面的核心任务是：把零散问题组织成一份可分享的问卷，让填写结果立刻变成看得见的统计信号。

## 方案比较

1. **研究脉冲台（采用）**：用脉冲、信号轨和填涂圆点连接设计、填写与分析，功能密度和品牌辨识度最平衡。
2. **纸张投票站**：亲切且容易理解，但多题型编辑和统计图表容易显得拥挤。
3. **通用数据后台**：适合结果分析，却会弱化填写体验，也容易与常见管理模板趋同。

## 视觉系统

- 薄荷纸面 #eef8f3：页面背景和研究台底板
- 深紫墨 #29264f：正文、边框和高对比结构
- 橙色 #ff7848：发布、提交和关键脉冲
- 青色 #48c7c4：成功、填写进度和数据轨道
- 柠檬黄 #ffe16b：提示、选中态和焦点强调
- 淡紫 #9b77d4：辅助数据系列
- 展示字：Arial Black / Microsoft YaHei，形成研究海报式标题
- 正文字：Segoe UI / Microsoft YaHei，保证表单阅读清晰
- 数据字：Cascadia Mono / Consolas，用于编号、百分比和状态

## 数据与交互

问卷包含 id、标题、说明和题目数组；题目支持单选、多选、短文本和 1–5 评分，可设置必答、增删和上下移动。设计页修改后实时保存到 localStorage，并同步更新右侧预览。

分享时将经过归一化的问卷 JSON 编码进 URL Hash。打开分享链接会直接进入填写模式，不依赖后端。答卷包含 surveyId、各题答案和提交时间，保存在填写设备的 localStorage 中；结果页只聚合与当前问卷 id 匹配的本地答卷。

## 静态托管边界

- 分享链接携带问卷结构，因此 GitHub Pages 上可以跨设备打开问卷
- 答卷仅保存在完成填写的当前浏览器，不会自动回传给问卷创建者
- 页面在分享面板与结果页明确展示这一限制，避免把演示误认为云端数据平台
- URL 解码失败、存储损坏或题目不合法时给出可恢复的错误提示

## 验收标准

- 四种题型可创建、编辑、设为必答、移动和二次确认删除
- 分享链接可编码、复制、刷新恢复并打开填写模式
- 必答校验、答题进度、提交回执和重复填写正常
- 单选/多选比例、评分分布与均值、文本反馈列表正确
- 本地答卷清空使用二次确认，页面明确静态存储边界
- 桌面与 390px 手机布局无横向溢出，键盘焦点清楚并尊重减少动态效果
- 追踪器显示 38/100，第 038 项链接和完成态正确
