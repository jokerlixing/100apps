# App 064 · GLYPH/64 AI 识图取字设计说明

## 产品目标

GLYPH/64 面向需要从截图、票据、扫描件和海报中快速取字的中文用户。页面只做一件事：把最多 12 张本地图片排成可控队列，在浏览器中逐张识别为可编辑文本，并导出单张或合并后的 TXT 文件。

图片像素始终留在当前浏览器，不上传到业务服务器。首次识别会从 CDN 下载 Tesseract.js 运行时和所选语言模型，后续资源可由浏览器缓存；界面必须把“本地处理”和“首次仍需联网下载模型”同时说清楚，不能把依赖下载误写成完全离线。

## 方案比较

1. **浏览器内 Tesseract.js 单 Worker 队列（采用）**：无需账号或 API Key，可部署到 GitHub Pages，图片不离开设备。官方建议多图识别复用一个 Worker；顺序执行还能限制内存并让中止与恢复更可预测。
2. **第三方 OCR API**：通常对复杂版面更准，但需要密钥、费用控制、后端代理和隐私告知，不适合当前纯静态挑战仓库。
3. **浏览器原生文本检测 API**：包体小、速度快，但兼容性和语言支持不足，不能作为跨浏览器核心路径。

Tesseract.js 固定为 7.0.0，通过用户首次开始识别时动态加载。应用创建一个 Worker，依次调用 `recognize`，批次结束后保留 Worker 供下一批复用；切换语言、中止任务或离开页面时终止 Worker。参考官方项目的 [浏览器与多图用法](https://github.com/naptha/tesseract.js/) 和 [Worker API](https://github.com/naptha/tesseract.js/blob/master/docs/api.md)。

## 功能范围

- 拖放、文件选择和剪贴板粘贴 PNG、JPEG、WebP、BMP 图片；单批最多 12 张，单张不超过 15 MB、3600 万像素。
- 内置一张中英混排样张，让用户无需准备文件也能理解工作流。
- 支持“简体中文 + 英文”“繁体中文 + 英文”“仅英文”三种模型；语言在批次开始时锁定。
- 可选“校样增强”：按最长边上限缩放，填充白底，再做灰度与对比度增强；原图不被改写。
- 队列逐张显示等待、加载模型、识别、完成和失败状态，显示真实进度；可中止当前批次并重新开始未完成项。
- 每张结果都可编辑、复制或下载；批次可导出带文件名分隔符的合并 TXT。
- 显示置信度、字符数和耗时。失败项保留在队列中并给出可执行的恢复提示。

不做账号、云端历史、PDF、版面表格还原、翻译和图片永久存储。刷新页面即清空图片与文本，避免在 localStorage 中留下用户内容。

## 信息架构与数据流

```text
本地图片 → 文件/像素校验 → 队列 → 可选 Canvas 预处理
                                      ↓
语言选择 → 动态加载 Tesseract.js → 单 Worker 顺序识别
                                      ↓
        队列状态 ← 文本/置信度/耗时 → 可编辑校样 → 复制/TXT
```

纯函数核心负责文件校验、语言配置、队列项更新、状态汇总、时长与大小格式化、安全文件名以及合并文本生成。浏览器控制器只负责 File/Blob、图片解码、Canvas、Worker 生命周期、DOM、剪贴板和下载。这样 Node 测试不需要真实 OCR 模型，也能覆盖所有状态和导出规则。

中止通过终止 Worker 实现。当前识别项恢复为“等待”，未开始项保持不变，已经完成的文本继续保留；再次运行只处理没有完成的条目。语言切换会在下一次运行前重建 Worker。

## 视觉方向

界面来自印刷厂的校样扫描台，而不是通用 AI 仪表盘。左栏像接触印样带，中央是带裁切标尺的透光玻璃，右栏是编辑校样。签名元素是一束只在真实 OCR 进度变化时移动的扫描光束；它负责传达状态，不作为无意义的循环装饰。

色彩令牌：校样纸蓝 `#e7edf2`、油墨黑 `#18232c`、扫描钴蓝 `#1f55d5`、定位洋红 `#d84e78`、校准黄 `#f2c94c`、玻璃青 `#bfe7ea`。标题使用 `Bahnschrift Condensed`，正文使用 `Aptos`/`Segoe UI`，数据与状态使用 `Cascadia Mono`/`Consolas`。

```text
┌ GLYPH/64 ─ 本地识别说明 ─ 语言 ─ 增强 ─ 开始批次 ┐
├─────────────┬──────────────────────┬──────────────────┤
│ 批次印样带   │ 透光预览 / 扫描光束   │ 可编辑文字校样     │
│ 01 等待      │                      │ 置信度 / 字数 / 耗时 │
│ 02 识别中    │      当前图片         │                  │
│ 03 完成      │                      │ 复制 / 下载单张     │
├─────────────┴──── 批次进度与状态 ───┴── 合并导出 ──────┤
```

桌面使用三栏工作台；窄屏改为“队列 → 预览 → 文本”的纵向流程。触控目标至少 44px，键盘焦点明确，扫描光束在 `prefers-reduced-motion` 下改为静态进度位置。

## 错误处理与验收

不支持的格式、超限大小或像素数在入队时拒绝，并保留其他有效文件。运行时分别处理依赖下载失败、语言模型失败、图片解码失败和单张识别失败；一张失败不能阻断后续图片。复制失败时保留可选中文本，下载始终使用本地 Blob URL 并及时释放。

核心测试覆盖文件限制、语言回退、不可变队列更新、状态汇总、安全文件名、合并导出、预处理尺寸和进度文案。浏览器验收覆盖样张入队、模拟识别、结果编辑、复制/下载按钮、删除与中止、桌面和 390px 布局、可见焦点、无横向溢出以及控制台无未处理异常。最终运行 Node 测试、语法检查、内部资源检查、追踪器测试、浏览器烟测、截图检查和 `git diff --check`。
