# App 038 文本与提示词生成问卷设计

## 目标与范围

在 PULSE/38 在线问卷系统中加入“输入需求 → 生成完整问卷 → 预览 → 应用 → 继续编辑与分享”的流程。用户可填写主题、参考文本、提示词和受访人群，在数字输入框填写 4–30 范围内的任意整数题数，选择单选、多选、短文本、1–5 评分等题型。生成结果包含标题、说明、题目、必答状态，以及选择题的选项。问卷规范化、编辑、存储恢复和分享流程统一支持最多 30 题。

保留现有静态问卷设计、分享、填写和统计能力。应用继续部署在 GitHub Pages，默认无需账号、密钥和后端。新增功能适配手机和平板，并更新根追踪器的说明与回归检查。

## 生成方式

默认本地模式使用主题识别、参考文本要点和题型模板生成初稿。界面明确说明其能力边界：它是规则与模板生成器，不能完整理解任意自然语言提示词。题目结构必须完整，用户可以在应用后继续编辑。

提示词中的明确题目和选项优先于参考文本与通用模板，并支持总题数、各题型数量和限定/排除题型等指令。已提供的题目先进入生成稿，再补全所需题数。总题数限定为 4–30；例如“共 12 题，6 道单选、4 道评分、2 道文本”应保留明确的数量分配。

可选 AI 模式由用户提供 HTTPS Chat Completions 接口完整地址、模型和 API Key。只有选择该模式并主动点击生成时，应用才向配置的服务发送本次生成参数；仅切换模式或编辑配置不触发请求。接口必须支持浏览器 CORS。返回内容先解析并校验为允许的问卷结构，再显示在预览区。网络错误和不合法结果显示可操作的错误提示，不覆盖当前问卷。

API Key 仅保存在页面内存，不写入 localStorage、问卷结构或分享链接。参考文本和提示词不设置应用级字符硬上限，输入、生成请求和存储恢复都不按预设字符数截断；生成输入在当前浏览器保存以便刷新继续。浏览器存储配额、设备资源以及服务模型上下文容量仍然有限，超出可用容量时可能保存或请求失败，需给出错误反馈。移除字符硬上限不意味着外部服务具备无限容量。分享问卷时仅编码问卷结构，不编码生成原文、提示词、服务配置或密钥。

## 状态与数据

生成表单和生成草稿独立于当前编辑问卷。生成完成仅更新待确认预览，不直接改动编辑器、已有题目或答卷。用户确认应用时，为问卷和题目创建全新 ID，并保存应用前的问卷用于一步撤销。已有答卷保持原来的问卷关联，避免被计入新生成问卷。

撤销用于恢复最近一次应用前的问卷；生成稿不是多版本历史系统。应用和撤销之后，编辑器、受访者预览及统计所使用的当前问卷保持一致。保存失败、非法分享载荷与损坏本地存储沿用明确反馈和安全恢复机制。

## 页面与移动布局

生成区放在设计流程的前部，集中显示输入、生成方式、题数和题型。生成按钮提供忙碌反馈，完整预览提供应用操作；生成完成后仍允许继续调整需求。AI 配置只在相关模式中展开，用户能在请求前了解发送内容。

桌面端维持 PULSE/38 的研究工作台视觉。窄屏将输入、配置和预览按操作顺序纵向排列，按钮与题型选择可换行，长文本和选项不撑宽页面。以 320px、390px、768px 和桌面尺寸检查横向溢出、触控目标、文本可读性、键盘焦点和问卷填写路径。

题目删除按钮显示完整“删除题目”与“确认删除”文字，字号为 18px，触控区域至少为 108×48px。首次点击进入 10 秒二次确认期，并保留键盘焦点；超时恢复默认状态，防止误删。窄屏动作栏允许换行，确保按钮文案可见。

## 既有数据边界

本项目没有答卷数据库。分享链接可跨设备携带题目，答案只保存在填写设备的浏览器，创建者无法自动汇总其他设备的回答。结果页只统计当前浏览器中与当前问卷 ID 相同的答卷。可选 AI 模式只用于生成问卷，不提供答卷云同步。

## 验证与交付

生成器检查覆盖空输入、长参考文本与提示词完整传递、4–30 整数题数及边界、题型数量分配、提示词明确题目与选项优先级、新 ID 和 AI 输出校验。浏览器检查覆盖本地生成与预览、应用与撤销、长文本刷新恢复、30 题编辑保存与分享、原有填写统计、移动端布局、删除按钮尺寸与确认焦点，以及 AI 请求成功与失败反馈。扫描运行时错误和敏感字段持久化路径。

根 `index.html` 保持 38 号官方名称“在线问卷系统”、原部署地址和完成状态，只更新能力说明；新增 `qa/tracker-app038.test.js` 检查条目及旧本地缓存迁移，并保留自定义项目。完成验证后由主任务统一提交并推送 GitHub `origin/main`，汇报开始、结束和耗时。
