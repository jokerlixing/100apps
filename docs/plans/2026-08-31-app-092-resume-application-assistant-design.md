# App 092 · 简历投递助手设计

## 产品定位

项目名定为 **FITROOM/92**。它面向需要同时投递多个岗位、但不想反复维护多份简历的求职者。页面的单一任务是：维护一份可信的母版资料，粘贴职位需求后生成可追溯、可编辑、可打印的定制简历版本。

产品不伪装成在线 AI 服务，也不编造候选人的经历。所有推荐都由本地关键词匹配和明确规则完成；生成动作只会重排、筛选和强调母版里已经存在的信息。数据仅保存在当前浏览器的 `localStorage`。

## 方案取舍

1. 纯简历编辑器：实现简单，但没有解决“一份数据生成多版本”的核心问题。
2. 完整投递 ATS：能覆盖公司、阶段和提醒，但会稀释简历版本生成的主任务。
3. 母版资料 + 职位版型 + 多版本输出：最贴合原题，且可以形成输入、匹配、生成、比较、导出的完整闭环。

采用方案 3。投递状态只作为版本上的一项轻量元数据，不扩展成独立看板。

## 信息架构与数据流

桌面端是三段式工作台：左侧是母版资料，中间是职位版型与版本衣架，右侧是可打印简历和岗位合身尺。移动端依次堆叠，版本导航固定在预览区上方。

```text
┌──────────────┬─────────────────────┬────────────────────────┐
│ MASTER 母版  │ ROLE CUT 职位版型   │ FIT RULER + 简历预览   │
│ 联系信息     │ 公司 / 岗位         │ 关键词覆盖 / 信息缺口  │
│ 技能         │ JD 文本              │ 当前版本内容            │
│ 经历 / 项目  │ 生成与版本衣架       │ 复制 / 打印 / 删除       │
└──────────────┴─────────────────────┴────────────────────────┘
```

母版资料经过规范化后写入本地状态。职位描述会被拆成稳定的关键词集合；生成器根据技能、经历和项目文本计算覆盖度，保留命中的内容，同时确保每类至少保留一项，避免产生空简历。版本保存生成时的匹配快照，之后可以通过“重新裁版”主动更新，防止母版修改悄悄改变历史版本。

## 视觉系统

- **裁床蓝 `#2447F9`**：主操作、当前版本和裁剪线。
- **图纸蓝 `#E8EEFF`**：画布底色和输入区域。
- **荧光珊瑚 `#FF6B61`**：风险、缺口和删除确认。
- **标记黄 `#FFD84D`**：匹配关键词与提示标签。
- **深墨蓝 `#101A35`**：正文、边框和高对比工作台。
- **纸白 `#FBFCFF`**：简历成品与浮层。

标题使用 `Bahnschrift SemiCondensed`，正文使用 `Aptos` / `Microsoft YaHei`，数据与版号使用 `Cascadia Mono`。布局不采用营销页大 Hero，而像一张正在工作的裁版台。视觉记忆点是右侧纵向“岗位合身尺”：刻度、覆盖率和缺口随职位内容变化，像量体裁衣的软尺。装饰只保留与版型、缝线、裁切标记有关的结构。

## 核心交互

- 母版字段失焦时自动保存；技能用逗号或换行分隔。
- 经历和项目使用结构化卡片，可新增、编辑、删除；至少保留一项。
- 输入公司、岗位和职位描述后生成新版本；缺少岗位或有效母版时给出具体修复提示。
- 版本衣架可切换、重命名、更新投递状态、重新裁版或删除。
- 预览中突出匹配关键词；支持复制纯文本、打印为 PDF、导出/导入 JSON 备份。
- 首访提供完整但明确标注为示例的候选人资料，用户可一键重置。

## 错误与隐私边界

- 非法备份、版本不兼容、空职位、母版内容不足都在界面内给出明确错误，不使用模糊的“失败”。
- 导入数据经过白名单规范化，不把备份中的 HTML 当作页面内容。
- 应用不发起网络请求，不上传个人信息，不承诺真实招聘结果或 ATS 排名。
- 打印动作使用浏览器原生打印对话框；“导出 PDF”由用户在打印目标中选择。

## 验证策略

- Node 单元测试覆盖：输入规范化、关键词提取、匹配评分、版本生成、版本重裁、纯文本导出、备份导入拒绝。
- 浏览器冒烟测试覆盖：母版编辑、生成版本、版本切换、状态更新、复制、导出备份、刷新持久化、错误提示、桌面/移动布局、键盘焦点和运行时错误。
- 视觉截图至少包含桌面完整工作台和移动端预览；检查横向溢出、触控目标和打印样式。
