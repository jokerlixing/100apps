# App 069 AI 面试模拟器设计

## 产品边界与用户路径

69 号应用命名为 **PANEL/69**，服务于正在准备中文技术、产品与运营岗位面试的求职者。页面只承担一条主路径：选定目标岗位与面试重点，完成一轮循序渐进的模拟问答，再拿到逐题证据评分和下一次练习建议。用户无需账号或 API Key 就能使用本地题库与评分引擎；服务器配置 AI 提供商后，可以在用户明确开启“AI 教练增强”时补充定制题目与更细的回答反馈。AI 不可用、超时或返回异常数据时，本地流程必须继续完成，并明确标注反馈来源。

准备台支持岗位方向、经验阶段、面试类型、题量、岗位描述和重点能力。面试席一次只展示一道题，保留真实面试所需的安静留白，同时提供进度、用时、回答文本、一次性思路提示、跳过和提交操作。每次提交后立即生成相关性、结构、证据和深度四维评分，并追问最明显的缺口；用户可以继续补答，也可以进入下一题。结束后生成总分、稳定与薄弱维度、逐题录音带式时间线、改进动作和可复制的复盘报告。最近三轮结果只写入当前浏览器，并提供明确清除入口。

核心闭环是“设定岗位 → 回答问题 → 接受追问 → 查看证据 → 再练一次”。第一版不加入真实视频、语音识别、摄像头情绪判断、账号、招聘方共享或职位投递，避免把无可靠依据的外貌和情绪识别包装成面试能力判断。评分是练习反馈，不代表真实录用概率。

## 架构、数据流与失败处理

`interview-core.js` 是零依赖 UMD 模块，负责配置归一化、稳定选题、关键词命中、STAR 结构与量化证据检测、四维评分、追问生成、场次汇总，以及 AI 题目和反馈的字段清洗。内置题库覆盖前端、后端、产品、数据、设计与运营，并混合自我介绍、行为、岗位专业和情境题；同一配置通过种子稳定生成计划，方便测试与恢复。

浏览器控制器维护准备、面试、逐题反馈、复盘与历史状态。提交回答时先同步产生本地评分，再在用户开启增强模式后向同源 `/api/coach` 发送当前题目、回答和最小化岗位上下文；有效 AI 反馈只增强文案，不覆盖本地可解释维度。生成题目也遵循相同策略：先得到完整本地题单，再尝试替换为经过清洗的定制题单。敏感的岗位描述和回答默认不离开浏览器，增强开关旁必须直接说明会上传哪些内容。

`server.js` 使用 Node 内置 HTTP、Fetch 与文件 API，不引入运行时依赖。密钥只从 `AI_API_KEY` 读取，模型和兼容端点由 `AI_MODEL`、`AI_BASE_URL` 配置。接口限制 JSON 请求体大小、动作类型、题目数量和回答长度；上游请求带超时，响应再次通过核心模块清洗。未配置、超时和异常响应只返回稳定错误，不泄露密钥、提示词或上游正文。单元测试覆盖选题、评分、追问、汇总与不可信 AI 数据；服务测试覆盖静态白名单、路径穿越、请求边界和代理失败；浏览器冒烟测试覆盖完整问答、复盘、历史恢复、桌面与移动布局。

## 视觉系统与响应式布局

视觉来自招聘面试控制室，而不是常见 AI 渐变仪表盘。色板为监控室蓝灰 `#DDE5EA`、深海军蓝 `#162536`、信号蓝 `#2457D6`、录制珊瑚 `#E85D4A`、评注黄 `#F3C969`、记录纸白 `#F8FAFB`。标题使用高密度的 `Bahnschrift Condensed` / `Microsoft YaHei`，正文使用 `Segoe UI`，计时、评分和题号使用 `Cascadia Mono`。结构标签只表达真实面试流程：`候场`、`面试席`、`追问`、`复盘室`。

桌面端上方是一条克制的会话状态梁；主体左侧为面试官问题与回答区，右侧是窄幅教练监听轨道。标志性元素是一盘纵向“回答磁带”：每次回答形成一段带真实时长、四维刻度和证据标记的磁带片，结束后展开为整场复盘时间线。唯一主动画是提交回答时磁带从输入区滑入监听轨道，其他区域不使用漂浮卡片或持续发光。准备页采用面试登记表式分栏，复盘页把总分压缩为清晰结论，把视觉重量留给逐题证据。

移动端将教练轨道移到回答区下方，底部操作保持可见但不遮挡输入，按钮触控区不小于 44px，长岗位描述与回答不造成横向滚动。所有交互有可见焦点，状态通过 `aria-live` 播报，图形评分保留文字数值；`prefers-reduced-motion` 下取消磁带位移动画。设计风险集中在“磁带”隐喻，其刻度必须承载真实评分与回答时长，避免退化为装饰。
