# App 073 论坛社区设计

## 产品定位与范围

73 号应用命名为 **THREADLINE/73**，面向愿意公开展示半成品、交换具体修改意见的独立创作者。页面的单一任务不是制造无限信息流，而是让用户沿着一条清楚的评审线完成：选择身份，浏览或筛选主题，发布带作品阶段与求助焦点的主题帖，点赞或收藏有价值的帖子，通过引用回复补充建议，再回到个人面板查看自己的贡献。默认内容围绕海报、独立游戏、摄影集、播客和手工作品，避免空泛的社交占位文案。

核心范围包括本地演示身份、服务端注册/登录、主题发布、标签筛选、最新/热门/待回应排序、点赞、收藏、评论、引用回复、个人资料与本人帖子。不会加入私信、图片上传、关注关系、管理员后台或通知推送；这些功能会扩大隐私、存储和审核范围，却不改善本次核心评审闭环。公开 GitHub Pages 使用 localStorage 提供完整可操作的演示社区，并明确显示“本地演示”；运行 Node 服务后，账号、会话和社区内容改由服务端 JSON 仓库持久化。

## 方案比较与架构选择

方案一是纯前端 localStorage，部署最稳定，但“用户系统”只能是浏览器内角色切换，无法诚实表达认证。方案二是只做服务端论坛，认证更完整，却会让公开 Pages 只剩不可操作的壳。采用方案三：**静态优先的共享领域核心 + 两种数据适配器**。同一套 `forum-core.js` 负责输入规范化、帖子/评论结构、排序、点赞和收藏切换；浏览器控制器在 `?offline=1` 或 API 不可用时读写本地数据，API 可用时使用服务端会话。

Node 服务只依赖内置模块。密码使用 `crypto.scrypt` 与随机盐保存派生值，不保存明文；会话令牌使用安全随机数并只返回给当前客户端。每个写操作都从服务端会话重新确定作者，客户端不能指定作者、点赞数或时间。仓库使用同目录临时文件加 rename 写入，并通过进程内队列串行化修改。请求体限制、静态文件白名单、稳定错误码和公开字段序列化共同控制演示边界。JSON 存储只适合单进程作品集，不宣称具备生产级扩展性或内容审核能力。

## 信息结构、数据流与失败处理

页面分为四个稳定区域：顶栏身份与模式状态、主题筛选工作台、主题列表、右侧个人/社区边栏。点击主题会打开详情抽屉，抽屉内按时间展示主帖、评论和引用来源；发布主题或回复使用原生 `<dialog>`，表单始终保留用户输入直到成功。移动端把边栏折叠为身份按钮，主题详情占满视口，并保留 44px 以上触控区域。

启动时客户端先尝试 `/api/bootstrap`。成功则读取当前会话用户、帖子与统计；失败或强制离线则载入一组不可变种子内容和浏览器自己的用户/互动记录。发布、回复、点赞、收藏均采用“先等待结果、再更新界面”的保守策略，避免网络失败时伪造成功；本地模式则同步写入 localStorage。重复提交由按钮 busy 状态和服务端幂等键共同处理。输入错误紧邻字段说明如何修复，身份失效会保留草稿并打开登录面板，空筛选结果提供清除条件按钮。

账号字段只包含用户名、显示名、简介和密码；公开内容不会显示密码哈希、会话或内部路径。本地演示身份不要求真实邮箱，并在界面与 README 中明确它不跨设备同步。用户可退出服务端会话；本地模式允许创建或切换多个演示身份，以便检查不同作者的权限和互动状态。

## 视觉系统与独特签名

视觉来源是创作者工作室里被图钉固定、用线索绳串联的评审卡，而不是通用社交产品。色板为工作台蓝 `#1848CF`、便签黄 `#F4C542`、图钉珊瑚 `#F05A47`、纸白 `#F7F8F2`、石墨黑 `#18202C`、批注薄荷 `#BFE7D2`。标题使用窄感强的 `Trebuchet MS`，正文使用 `Aptos` / `Segoe UI`，标签与计数使用 `Cascadia Mono`。卡片保持小圆角和清晰边框，阴影只用于当前打开的主题。

桌面布局不是三列社交面板，而是一条横向“评审线”：左侧筛选像工作夹，中间帖子卡沿一根蓝色竖线排列，每张卡左缘有真实表达时间顺序的节点，右侧是个人票夹。主题详情继续这根线，用珊瑚色短线连接引用回复。这条可追踪的线索是唯一视觉风险与记忆点；其余背景、按钮和信息层级保持克制。

```text
┌ 身份 / THREADLINE / 模式 ───────────────────────────┐
│ [筛选夹]  ●── 主题卡：阶段、焦点、作者        [我的票夹] │
│           │   主题摘要 / 标签 / 互动                 │
│           ●── 主题卡                                 │
│           │                                          │
│           ●── 主题卡                    [发布主题]    │
└──────────────────────────────────────────────────────┘
```

移动端去掉固定侧栏，但保留左侧时间线和节点作为阅读锚点。唯一主动画是打开主题时“线索绳”从卡片延伸到详情；`prefers-reduced-motion` 下立即切换。键盘焦点使用便签黄外环，状态变化进入 `aria-live`，色彩对比与文本标签不依赖颜色单独传达。

## 验证标准

- 领域测试覆盖账号字段、帖子与评论输入、公开序列化、排序、点赞/收藏幂等切换、作者权限和引用有效性。
- 服务测试覆盖静态白名单、路径穿越、请求体上限、注册/登录/退出、会话隔离、发帖、回复、互动、持久化恢复和错误脱敏。
- 浏览器冒烟覆盖本地身份、新主题、主题筛选、点赞收藏、引用回复、刷新恢复、服务端注册登录、桌面与 390px 布局、键盘焦点和运行时错误。
- README 说明两种运行模式、隐私与存储限制、API、测试命令和公开地址；根追踪器在项目代码先推送后再登记 73 号链接与完成状态。
