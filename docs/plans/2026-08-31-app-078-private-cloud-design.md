# App 078 私人网盘设计

## 产品边界与核心路径

78 号应用命名为 **DEPOT/78**，服务于希望把少量私密资料留在自己设备上，并能清楚知道“存了什么、占了多少、分享给谁”的个人用户。页面只承诺浏览器本地资料库：文件正文进入 IndexedDB，文件夹、分享口令、回收站和界面偏好同样保存在当前浏览器，不上传到第三方，也不声称具备账号、跨设备同步或真正的公网分享能力。公开 GitHub Pages 版本会在页首和分享对话框中明确说明这一边界。

核心路径是“入库 → 归档 → 查找 → 借出 → 回收”。用户可拖放或选择多个文件，系统在写入前检查单文件大小、逻辑配额、空文件名和同目录重名；成功后可按文件夹、类型、共享状态和回收站筛选，搜索名称，切换排序，在右侧检视卡中预览支持的图片、音视频和文本。资料夹可删除，夹内文件会在同一存储事务中迁回总库并保留原回收状态。下载使用浏览器 Blob URL，删除先进入回收站，可恢复或永久删除。分享会生成本地口令和带 URL fragment 的链接，并支持 1、7、30 天或长期有效；打开链接时仅在同一浏览器资料库中解析，失效或缺失会给出明确恢复建议。

逻辑配额固定为 512 MiB，不冒充浏览器真实磁盘上限。容量台账按文档、图片、媒体和其他类型显示真实已存字节；测试模式可使用更小配额验证拒绝路径。首访会写入三份可下载的示例文本资料，帮助用户立即理解流程，之后不会重复覆盖。所有销毁操作均需明确二次确认。

## 架构、数据流与失败处理

采用零依赖静态优先架构。`file-core.js` 是 UMD 纯领域层，负责文件名清洗、同名消解、类型归类、字节格式化、配额计算、上传校验、搜索排序、分享口令与有效期判断；它不接触 DOM 和 IndexedDB，可由 Node `node:test` 直接覆盖。`storage.js` 封装版本化 IndexedDB，分别保存文件（含 Blob）、文件夹和设置，并提供 Promise API。`app.js` 只负责视图状态、事件委托、预览 URL 生命周期和可访问性提示。

上传先读取现有目录与文件元数据，在内存中完成整批校验，再逐项写入 IndexedDB；任何单项失败都会保留其余成功项，并在结果提示中列出失败原因。浏览器拒绝存储、达到实际磁盘上限、私密模式限制或数据库迁移失败时，页面进入可恢复错误态，既不清空已有数据，也不显示虚假成功。预览只读取当前选择文件；文本预览限制为前 64 KiB，Blob URL 在切换选择时立即撤销。分享链接把不敏感的随机口令放在 fragment 中，不把文件内容或名称写入 URL。

取舍上不增加 Node 服务、登录和加密。静态部署无法诚实提供跨设备分享；浏览器端自制加密也不能替代可靠密钥管理。DEPOT/78 的完成标准是把本地文件生命周期做完整、可验证、无误导，而不是搭出一个外表像商业云盘但无法兑现的后端壳。

## 视觉系统与响应式布局

视觉来自社区档案馆的滑轨密集柜与纸质借阅卡，而不是通用蓝白云盘。色板为库房灰蓝 `#D8E0DF`、档案墨绿 `#173F3A`、索引砖红 `#C9503D`、标签芥黄 `#E7C45B`、棉纸白 `#F6F2E8`、铅字黑 `#17201F`。标题使用 `Arial Narrow` / `Bahnschrift Condensed`，正文使用 `Segoe UI` / `Microsoft YaHei`，容量、日期、口令与文件编号使用 `Cascadia Mono` / `Consolas`。

桌面端左侧是带真实计数的柜列索引，中间是可拖放的“入库轨道”和密集文件台账，右侧是会随选择变化的借阅卡。签名元素是一根垂直容量尺：每次文件写入或销毁时，刻度只随真实字节数移动一次，类型色段对应真实容量构成。文件不是卡片瀑布流，而是像档案目录一样用行、列、编号和状态章表达结构；唯一显著的砖红色只用于“入库”和危险操作。

移动端先显示入库动作与当前资料台账，柜列索引变为横向筛选条，检视卡以原生 `<dialog>` 打开。所有主要触控区不小于 44px，焦点环可见，状态写入 `aria-live`，键盘可完成筛选、选择、下载、分享与回收。`prefers-reduced-motion` 下取消容量标尺和新文件入轨的位移。1440px 与 390px 都不得产生页面横向溢出。
