# App 058 网页性能检测器设计

## 产品目标

为 100 Apps Challenge 制作一个可直接部署到 GitHub Pages 的网页性能工作台。用户输入公开的 HTTP(S) 地址并选择移动端或桌面端后，应用调用 Google PageSpeed Insights v5，展示 Lighthouse 实验室性能分数、核心指标、优化机会和请求瀑布摘要。无密钥额度受限或网络不可用时，用户仍可加载内置示例，完整体验结果阅读流程。

页面只解决一个问题：让前端开发者在一分钟内知道页面慢在哪里，以及下一步最值得做什么。

## 方案选择

1. **PageSpeed Insights 实时审计（采用）**：能真正检测任意公开网址，返回标准 Lighthouse 数据；代价是一次审计通常需要几十秒，并受公共 API 限流影响。
2. **浏览器 Navigation Timing**：不依赖第三方接口，但只能可靠测量当前页面，不能满足“输入网址检测”。
3. **纯本地模拟评分**：最稳定，却只能作为演示，不足以成为可用工具。

采用方案 1，并用方案 3 作为明确标注的降级示例。应用不伪造实时结果，也不要求用户填写或暴露 API Key。

## 视觉方向

主题是“网络飞行记录器”，不是通用数据仪表盘。界面像一张正在走纸的诊断记录：输入区是一条发射轨道，结果区用刻度、时间条与单色数据字组成一份可读的性能底片。

- **雾蓝纸 `#e9edf6`**：页面底色和轻量网格。
- **深海墨 `#172033`**：正文、边框和主要结构。
- **仪器蓝 `#3157d5`**：活动状态、链接与性能轨迹。
- **警报橙 `#f15a3d`**：差指标和高优先级机会。
- **校准青 `#5fd0bd`**：良好指标和完成状态。
- **示踪黄 `#f4c95d`**：处理中与需要改进的指标。

标题使用 `Bahnschrift SemiCondensed / Arial Narrow`，正文使用系统无衬线，数值与状态使用 `Cascadia Mono / Consolas`。不加载网络字体，避免性能工具自身制造额外请求。

### 页面骨架

```text
┌ PULSELINE / WEB DIAGNOSTICS ─────────────── 058 ┐
│  [ https://example.com________________ ] [RUN] │
│  device: ● mobile ○ desktop     [view sample] │
├───────────────────────────────────────────────┤
│  score / grade   │ FCP  LCP  TBT  CLS         │
│  circular trace  │ metric cards + thresholds  │
├──────────────────┴────────────────────────────┤
│  request waterfall / diagnostic trace         │
├───────────────────────┬───────────────────────┤
│  opportunities        │ recent local runs     │
└───────────────────────┴───────────────────────┘
```

签名元素是“诊断示踪带”：审计中显示扫描脉冲；完成后变成按请求开始时间和持续时间排列的微型瀑布图。动效只服务于这一个状态转换，并遵守 `prefers-reduced-motion`。

## 交互与数据流

1. URL 规范化：缺少协议时补 `https://`；仅接受 `http:` 和 `https:`；拒绝含用户名/密码、localhost 与私网地址。
2. 点击“开始检测”后锁定表单，显示阶段进度和可取消按钮，通过 `AbortController` 提供 90 秒超时。
3. 请求 `runPagespeed`，携带 `url`、`strategy`、`category=performance` 与中文 locale。
4. 解析 Lighthouse 结果，统一生成页面使用的报告模型，不让视图直接依赖庞大的原始 JSON。
5. 渲染总分、FCP/LCP/Speed Index/TBT/CLS、最多 5 条高价值优化机会，以及最多 12 条体积较大的网络请求。
6. 最近 6 次成功实时检测写入 `localStorage`。仅保存摘要，不保存完整 API 响应。
7. API 失败时展示具体原因和“加载示例报告”操作；示例始终带有清晰的“示例”标记，不写入历史。

所有远端 URL、标题和错误信息都通过 `textContent` 输出。链接只使用经过 URL 校验的 HTTP(S) 地址。

## 空状态、错误与边界

- 首屏用简短说明和静态轨迹示意引导输入，不预先伪装成检测结果。
- 无效 URL 在输入框下就地说明修复方式。
- 私网、localhost 和带凭据地址明确拒绝，因为远端 PageSpeed 无法安全访问。
- 429 显示公共额度繁忙；403 显示服务拒绝；超时提示稍后重试；其他错误保留可读摘要。
- 缺少某个 Lighthouse 指标时显示 `—`，而不是 `0`。
- 无优化机会时显示“未发现高优先级机会”，不留空白板块。

## 验收标准

- 纯静态文件可从 GitHub Pages 打开，无构建步骤、无外部运行时依赖。
- URL 校验、API URL 构造、报告解析、分数分级和历史清理具备 Node 自动化测试。
- 实时 API 成功时可读出标准 Lighthouse 数据；失败时可一键进入明确标记的示例报告。
- 键盘焦点可见，状态变化通过 `aria-live` 宣告，移动端 360px 宽度无横向溢出。
- 根追踪器第 058 项更新为 `TRACE/58`，链接到 `apps/058-web-performance/`，并加入完成列表。
- README 说明功能、数据来源、隐私边界、运行方法和测试命令。
