# #038 PULSE/38 在线问卷系统

一个面向工作坊主持人、产品研究者和小团队的零依赖问卷工具。从主题、参考文本和提示词生成完整问卷，再校对、编辑、分享和查看本地结果。

[在线使用](https://jokerlixing.github.io/100apps/apps/038-online-survey/)。本地模式无账号、无后端、无外部依赖；联网 AI 模式由用户自行配置兼容服务。

## 功能

- **文本生成问卷**：输入调查主题、参考文本、提示词与受访人群，选择 4–20 题和所需题型，生成标题、说明与完整题目
- **两种生成方式**：默认本地规则与模板生成，也可选择用户配置的 AI 服务理解较复杂的文本要求
- **先预览后应用**：完整展示生成稿，确认后再应用；支持一步撤销，保留已有答卷
- **问卷设计**：编辑标题与说明，实时保存草稿
- **四种题型**：单选、多选、短文本、1–5 评分
- **题目管理**：新增、修改、必答开关、上下移动、选项管理和二次确认删除
- **实时预览**：设计页右侧同步展示受访者看到的问卷
- **URL 分享**：将规范化问卷编码进 Hash，复制链接即可跨设备打开
- **填写体验**：答题进度、必答校验、提交回执和再次填写
- **结果分析**：选择题比例、评分分布与均值、文字回答列表、答卷脉冲带
- **本地持久化**：问卷草稿与答卷保存在 localStorage
- **安全与恢复**：文本统一 HTML 转义，非法分享载荷和损坏存储自动回退
- **响应式与可访问性**：桌面/移动布局、键盘焦点、语义表单与减少动态效果

## 生成问卷

1. 在生成区填写调查主题、参考文本或提示词；受访人群可补充问卷的措辞背景。
2. 选择题目数量（4–20）和题型，可组合单选、多选、短文本与 1–5 评分。
3. 默认使用本地生成。若需要模型理解复杂要求，切换到 AI 模式，并填写 HTTPS Chat Completions 接口完整地址、模型名称和 API Key。
4. 生成后检查标题、说明、题目和选项，确认后应用到编辑器，再继续手动修改或分享。
5. 应用后的问卷使用新问卷 ID 和题目 ID。旧答卷保留在当前浏览器，不会混入新问卷统计；需要恢复原问卷时可立即使用一步撤销。

提示词中的明确题数、限定/排除题型优先于界面设置，例如“生成六道题，只要单选题，全部选答”。可按以下格式粘贴现有题目，生成时优先保留并补全剩余题目：

```text
1. 您最近一个月就餐的频率是？ [单选]
A. 每周多次
B. 每周一次
C. 偶尔
2. 您希望优先改进什么？ [文本]
```

本地生成器使用主题识别、文本要点与题型模板，适合快速搭建初稿，**不能完整理解任意提示词**。生成内容需要结合调查目的校对，尤其是选项完整性与问题是否中立。AI 输出也会经过结构校验，再供用户预览。

生成输入保存在当前浏览器，方便刷新后继续。API Key 只留在当前页面内存，不写入本地存储或分享链接。AI 模式仅在用户主动点击生成时向所配置的服务发送本次主题、参考文本、提示词和受访人群等生成参数。请仅填写愿意交给该服务处理的内容；接口需支持浏览器跨域请求（CORS）。本地模式不发送生成内容。

## 静态分享边界

这个应用部署在 GitHub Pages，不包含数据库或服务端：

1. 分享链接携带的是问卷结构，因此题目可以跨设备打开。
2. 答卷保存在填写者当前浏览器，不会自动回传给创建者。
3. 结果页只统计当前浏览器中、问卷 id 相同的答卷。
4. 分享链接不包含已有答卷，也不包含生成输入或 API Key。分享和答卷功能不会上传答案；可选 AI 生成是单独的联网功能。

这个边界会在分享面板、填写页和结果页持续提示，避免把本地演示误解成云端问卷平台。

## 数据结构

~~~javascript
{
  survey: {
    id,
    title,
    description,
    questions: [{ id, type, title, required, options }]
  },
  responses: [
    { id, surveyId, submittedAt, answers: { [questionId]: value } }
  ]
}
~~~

## 视觉设计

界面取材自研究工作台和光学答题卡：深紫结构承载问卷逻辑，橙色表示正在传递的答案，青色和淡紫组成统计信号，柠檬黄用于选择与提示。结果页的“答卷脉冲带”让每份提交变成一个可见圆点，是贯穿整个应用的标志性元素。

## 技术栈

纯 HTML / CSS / JavaScript，无框架、无构建步骤。默认本地生成无需网络；可选 AI 模式使用浏览器 `fetch` 调用用户配置的 HTTPS Chat Completions 接口。

## 验证

- 生成器测试覆盖输入约束、题型/题数、生成结构与服务返回校验。
- 交互验证覆盖生成预览、应用、撤销、草稿恢复及原有填写和统计流程。
- 移动布局检查覆盖 320px、390px 和 768px，并兼顾桌面展示。
- 根追踪器回归：`node --test qa/tracker-app038.test.js`。

运行 `node --test apps/038-online-survey/generator.test.js qa/*.test.js` 检查生成器和追踪器。浏览器回归需要 Playwright：在仓库根目录启动 `python -m http.server 8038 --bind 127.0.0.1`，再运行 `node --test apps/038-online-survey/browser.test.cjs`。可通过 `PULSE38_TEST_URL` 覆盖测试地址。

AI 自动化验证使用模拟服务，覆盖成功、非法结果、失败、取消与密钥隔离；真实服务的可用性取决于用户配置的地址、模型、密钥及 CORS 支持。
