# App 065 AI 语音转文字设计

## 产品边界

65 号应用命名为 **SCRIBE/65**，面向需要把访谈、灵感口述和会议速记立即整理成文本的中文用户。页面只完成一条闭环：开始听写、获得带时间的文本段、校对内容、导出 TXT 或 SRT。首版不做账号、云端历史、说话人识别或 API 密钥配置；录音、转写稿和偏好都留在当前页面或当前浏览器。

应用优先使用浏览器提供的 `SpeechRecognition`/`webkitSpeechRecognition` 实时识别麦克风输入，同时用 `MediaRecorder` 在用户明确允许后保留本次录音，供回放和下载。语音识别由浏览器服务完成，不承诺离线可用。浏览器不支持、权限被拒绝或自动化验收环境没有麦克风时，页面会解释原因并允许载入一份明确标注的演示转写；演示不能伪装成真实识别结果。导入音频只用于本地回放和人工校对，因为浏览器原生识别不能可靠地直接读取文件音轨。

## 交互与数据流

首屏是一台横向“广播转写台”。左侧是实时声带、录音时长、语言与开始/暂停控制；右侧是逐段稿纸。识别中的临时结果显示在走带游标旁，最终结果才写入段落列表。每段保存开始毫秒、结束毫秒、文本和来源，允许直接编辑或删除。停止听写后仍可回放录音、搜索稿件、复制全文、下载 TXT 或生成标准 SRT。

会话状态以版本化 JSON 写入 `localStorage`，只保存最终文本段、语言和会话标题，不保存音频 Blob。页面刷新后可恢复稿件；新建会话需要二次确认，避免误删。录音 Blob 只存在内存中，离开页面即释放。所有持久化数据进入核心模块前都要清洗，空段、非法时间和过长文本会被拒绝或修正。临时识别结果不持久化，避免刷新后留下半句。

## 视觉方向

视觉取材于电台录音棚里的走带机和校对稿，而不是常见的深色 AI 仪表盘。色板为磁带蓝 `#15283d`、录音红 `#e64b3c`、监听青 `#5bbec2`、电平黄 `#f1c75b`、稿纸白 `#f4f3ed`、铅字黑 `#17212b`。标题使用 Windows 常见的 `Bahnschrift SemiCondensed` / `Arial Narrow`，正文使用 `Segoe UI` / `Microsoft YaHei`，时间码使用 `Cascadia Mono` / `Consolas`。

签名元素是一条真正响应音量或演示节拍的“磁带声带”：竖向播放头固定在中央，波形从右向左经过它，段落时间码与声带刻度使用同一时间基准。页面其余区域保持安静，以细刻度、纸张装订孔和实体按键传达工具感。唯一的持续动效是录音时的波形位移；`prefers-reduced-motion` 下改为静态电平。移动端把控制台折成上方录音台和下方稿纸，按钮触控区域不小于 44px。

## 错误与无障碍

麦克风权限拒绝、识别服务不可用、录音编码不支持和存储损坏都有具体的下一步提示。开始、暂停、恢复、停止、导出和删除都会通过可见状态条与 `aria-live` 同步反馈。页面只有一个 `h1`，所有图标按钮有文字或可访问名称，键盘焦点清晰，颜色不是状态的唯一载体，实时临时文本使用 `aria-live="polite"`，录音计时不会高频打断读屏。

## 验证标准

核心单测覆盖文本清洗、段落归一化、排序、编辑/删除、指标统计、TXT/SRT 时间码、文件名和损坏存储恢复。浏览器冒烟测试覆盖演示会话、编辑、搜索、删除、复制/下载入口、刷新恢复、新建清空、桌面与 390px 手机布局、无横向溢出、可见状态以及控制台无未处理错误。真实麦克风流程需要在 Chrome 或 Edge 的安全上下文中人工验收，并在 README 中明确列出。
