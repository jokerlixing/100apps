# App 049 截图框选区域录制

## 需求与交互

在现有「开始录制」按钮上方增加「截图录制」。点击后通过浏览器共享面板取得用户选择的屏幕、窗口或标签页，再将当前画面截图呈现在选区对话框中。用户拖动矩形框选需要录制的位置，确认后沿用现有倒计时与录制流程。截图只用于确定区域，最终录制该区域的实时画面。

框选支持任意拖动方向、重新框选、取消及键盘操作；区域未有效选定时不可确认。截图按比例适应可用空间，显示坐标转换为源画面像素坐标，避免页面缩放或高分辨率共享源导致录制位置偏移。现有直接录制完整共享源的入口继续可用。

## 技术方案

采用已授权的视频流生成截图，将选区保存为源画面的固定矩形。录制时把视频新帧的相同矩形绘制到输出 Canvas，再使用 `captureStream()` 生成裁剪后的视频轨道，并复用现有共享音频、麦克风混音、MediaRecorder、暂停、结束、回放与下载逻辑。选区外的像素不绘入输出画布。

此方案可覆盖屏幕、窗口和标签页三种共享源。浏览器专用的 Region Capture API 受共享目标和浏览器能力限制，无法单独覆盖现有功能；仅用 CSS 裁剪预览不会改变下载文件，因此不适用。

框选与裁剪的坐标换算、帧输出及释放逻辑集中在 `region-capture.js`，由 `app.js` 管理权限、对话框和录制生命周期。新增流程不引入服务端、上传接口或第三方依赖。

## 生命周期与边界

取消共享或框选时释放已经取得的媒体轨道，不启动录像。重复点击、录制中更改选区、无效矩形及截图读取失败都有明确状态处理。结束录制、浏览器停止共享及页面退出时停止裁剪循环、释放视频与音频资源。

选区固定于授权源，不追踪其中移动的内容。共享源的像素宽高变化时结束录制并保留已经完成的片段，提示用户重新选择，避免以过期坐标录入原定区域之外的内容。浏览器仍会授权整个共享目标，产品文案明确说明先授权、再框选的顺序。

## 验证与交付

单元测试覆盖正向与反向框选、缩放坐标、边界裁剪、过小或无效区域和输出尺寸。浏览器验证检查按钮顺序、截图选区、取消、裁剪帧像素范围、确认后的实时画面、实际录像回放及音频、暂停与恢复、源尺寸变化和资源释放，并回归现有完整画面录制。无头浏览器切换标签页仍报告可见，因此未将其作为隐藏标签页录制验证；裁剪调度使用 Worker 心跳，避免依赖后台会暂停的动画帧。
